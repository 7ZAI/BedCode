# 对等网络信任模型：两级信任 + 首次连接确认，而非逐对配对

## 背景

对等网络中任意两端（包括从未接触过的两部手机）需要建立信任，而现有认证体系（配对码 / QR 令牌 / 生物认证 / 会话令牌）全部是「移动端 → 桌面主机」的单向客户端-服务器概念，在对等语义下失效。需回答：两个从未谋面的设备在同一 WiFi 里凭什么互信、信任的确认动作是什么形态、与既有终端配对体系如何交接。

## 决定

采用**两级信任模型**：

1. **未信任节点纯可见、零交互**——已发现但未建立信任的节点不能发传输请求、不能浏览共享目录；
2. **首次连接确认**——发起方点击连接后，被连接方收到应用内一次性确认弹窗：同意即建立逐对、双向、持久的信任关系（本地存对方节点 ID = Ed25519 公钥指纹），拒绝则本次失败可重试；此后两节点间连接静默、不再弹窗；信任可在设置中撤销。不强制扫码；
3. **终端配对迁移**——已有终端配对关系的设备对首次对等接触免确认直接互信（终端配对记录即同一用户的证明），用户不为同一桌面配第二次。

信任层只回答「谁有权向我发起交互」；传输放行仍由全局接收策略（每次询问/直接接收/直接拒绝）独立把关，二者正交。

## Considered Options

- **零配置全信**：发现即可连，仅靠接收策略兜底——恶意同网节点可枚举设备名、反复弹请求骚扰，且共享目录浏览永远无法安全开放。
- **逐对显式扫码配对**（复用现有配对码/QR 体验）：最强但 O(N²) 操作负担，4 台设备需配 6 次。
- **首连强制扫码**：可防「同网攻击者抢答确认弹窗」的边缘场景，体验成本压倒收益边际，v1 不做。

## Consequences

- 节点身份随 App 安装生灭：重装即新身份，需重新走一次首连确认。
- 「直接接收」模式下文件静默落盘的前置防线是信任层——只有可信对端能走到接收策略这一关。
- 可信对端免询问白名单留作后续选项，v1 接收策略维持全局粒度不区分对端。
- 终端控制链路的认证体系原封不动：终端配对授予「操控电脑」级权限值得独立强认证，不为「传个文件」强迫用户走完整配对。
