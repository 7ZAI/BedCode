# 代码查看器：窗口扩大插入面板，终端视口尺寸不变

## 背景

终端窗口是独立 `WebviewWindow`（`terminal-<sessionId>`，约主窗口 60% 宽、等高、贴主窗口右侧、`resizable: true`）。终端尺寸是 PTY 驱动的：xterm 以视口尺寸算 cols/rows，仅当二者实际变化时才向后端重新协商（`TerminalResizeDebouncer` + DPR 感知）。

目标场景是 vibe coding：Claude Code 在终端里持续产出，用户需要并排查看代码文件。关键张力是**终端渲染画面必须稳定**——PTY 重协商会触发整屏 reflow 与滚动缓冲重绘，打断"AI 在工作、我在观察"的连续性。

## 决定

**展开 = 窗口几何操作，不是面板塞入现有空间**：

1. 点击终端工具栏按钮 → 终端窗口向右扩大固定面板宽度（默认 420 逻辑像素），代码面板占据扩大出的新空间，位于终端视口右侧；
2. 展开期间终端视口保持展开前的像素尺寸不变——PTY cols/rows 完全不重协商；
3. 面板打开后用户手动拖拽窗口变宽：终端视口锚定不再谈判，面板吸收全部尺寸变化；
4. 收起：严格恢复展开前的窗口矩形（位置 + 尺寸），一次动作移除面板；
5. 屏幕右缘钳制：扩大后超出屏幕边界时钳制到剩余空间；剩余空间 < 300 逻辑像素则拒绝展开并提示（不把窗口整体左移压住主窗口——主窗口与终端窗口的相邻关系是贴靠联动的前提，不允许破坏）。

面板宽度为窗口扩大增量 + 终端窗口宽度变化面的唯一吸收者，二者是一枚硬币的两面。

## Considered Options

- **现有窗口宽度内左右分割（终端重排）**：实现最朴素（一个 flex 容器加面板），但终端 cols/rows 变化 → PTY 重协商 + 缓冲 reflow，违背场景核心诉求；且回缩时再次重协商，往返抖动。
- **窗口放大 + 终端等比放大、面板横向挤占**：多出一层几何计算，且终端变大并非用户所求——用户要的是"看代码"，不是"更大的终端"。
- **独立第二个代码窗口**：绕开几何问题但割裂观察上下文（两个窗口贴靠联动、焦点跳转、贴靠状态都要新逻辑），且与「嵌入终端窗口」的用户意图相悖。
- **窗口扩大 + 终端视口锚定（本决定）**：终端画面零扰动，窗口/面板几何由一条命令域统一管理，收起时确定性恢复。

## Consequences

- `useSessionWindows.ts` 需记录展开前的窗口矩形（pre-expand rect），收起时用它恢复；窗口状态增加 `codePanelOpen: boolean` 标记。
- 展开态下主窗口贴靠联动（`checkAndSnap` 用旧宽度计算）需复核：主窗口移动时终端窗口跟随，展开期间宽度已变，跟随逻辑不得把扩大后的窗口推回原宽。
- 手动拖拽变宽 → 面板吸收 → 收起时恢复 pre-expand rect 而非当前宽度（用户拖宽的部分在收起时间一并丢弃，这是本决策的显式语义）。
- 屏幕空间不足时的"拒绝展开"需要一个用户可理解的提示文案（i18n 双端 key）。
- 面板宽度固定值未来可放开为拖拽调节（分割线），不改变本决策的锚定原则。
