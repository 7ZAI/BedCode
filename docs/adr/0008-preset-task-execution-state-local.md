# 预设任务执行状态 —— 手机本地记录，入队即锁定，广播仅细化展示

---
status: accepted
---

移动端预设任务与自动任务队列此前不成闭环：预设任务可无限次加入队列，且队列项不关联预设任务。我们决定：预设任务的执行状态完全记录在移动端本地（预设任务是轻量本地数据，卸载即清零，不值得入服务端表）；**入队动作即视为"已执行"并锁定**——锁定依据是用户本地操作（可靠），而非服务端任务终态通知（广播不可靠：应用退出、通知丢失都会丢）。服务端完成广播仅用于细化展示：收到即"已完成"，对账无则"已中断"；中断同样锁定、无重试路径。编辑任务内容或从队列移除任务是仅有的解锁路径。

## Considered Options

- **服务端持久化关联**（task_queue 加 source_preset_id 列，入队 API 携带预设 id）：判定权威、跨会话一致，但预设任务数据进入服务端表，违背"手机预设任务轻量、卸载即重置"的定位，且需跨端协议与 schema 迁移。否决。
- **终态（done）才锁定 + 轮询对账**：依赖服务端终态，应用退出后通知丢失会导致已执行的预设可再次入队（重复执行）；且现有队列接口不含终态项，对账无法区分"已完成"与"被删除"。否决。
- **入队即锁定 + 广播细化**（选定）：锁定看可靠信号（用户操作），展示看尽力信号（广播）；对账（面板打开/应用启动）时无完成广播的任务落"已中断"，同样锁定。

## Consequences

- 桌面端 auto-task 插件需补"任务完成广播"：任务终态 done 时广播 `TaskQueueChanged`（扩展携带 `task_id` + `status`），复用宿主 sync_handler → 移动端 WebSocket 链路；移动端入队时以 `httpTaskQueueAdd` 返回的 `task_id` 建立预设 → 队列项本地关联。
- 同一预设任务同一时刻队列至多一个实例（防重复），对可重复/不可重复统一生效；可重复任务在完成/中断后恢复可入队。
- 手动执行（toolbox 直接发送）成功即本地标记"已执行"。
- 手机重置/卸载后本地状态清零，旧队列项成为孤儿记录，不影响新循环。
