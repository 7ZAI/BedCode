# 远程访问采用可信中继模型：传输层 TLS，不做端到端加密

远程访问（内网穿透）经由用户自购云服务器作为中继（Relay）：中继视为可信节点，移动端↔中继、中继↔桌面端插件两段公网链路均以 TLS 加密并在中继处终止，业务流量（WebSocket + HTTP）在中继内部明文转发至隧道，不做端到端加密。证书采用自有域名 + Let's Encrypt 正式证书，两端均走系统 CA 信任，不引入自签名 CA 注入。

选择可信中继而非端到端加密的理由：中继运营者即用户本人，接受其可见全部业务流量的残余风险；端到端加密需协议级改造（密钥协商 + 消息负载加密），且移动端生物密钥（P-256）当前仅为 SIGN 用途、不可直接用于 ECDH，改造代价与收益不成比例。曾考虑自签名证书 + 插件携带 CA 的路线，因需移动端宿主 TLS 注入（WS 与 HTTP 两处）且 CA 私钥无吊销机制而放弃。

**Consequences**: 中继被攻破或云厂商可访问即等于业务流量泄露（已接受）；桌面端 JWT 密钥硬编码问题在公网暴露前必须修复；配对码等弱凭据需在公网暴露下加强限速。
