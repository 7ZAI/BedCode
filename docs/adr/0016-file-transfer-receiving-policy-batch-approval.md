# 文件传输接收策略与异步批量批准协议

上传不再无条件接收：接收端插件新增配置「接收策略」（每次询问 / 直接接收 / 直接拒绝，默认每次询问）。每次询问模式下，发送方先发批量传输请求（`POST /transfer-request`，批 ID + 文件清单 + 总大小），接收方以「接受全部 / 拒绝全部」一次应答，超时（默认 60s，可配置）自动拒绝；批准后批内文件 session 免问直接传输。这推翻了 v1 的两个定案：① spec 第 8 节「配对 + 白名单即完整信任模型，无第二层开关」——接收策略成为第二层放行开关（用户显式要求）；② spec 4.2 的同步钩子裁决（allow/deny、2s 超时 fail-closed）——异步人审装不进同步钩子，改为三路钩子（allow/deny/ask）+ 宿主 pending 批状态 + 宿主 approve/reject 命令 + WS 控制面推送。批量请求的动机：默认策略是每次询问，而逐文件询问在整批场景（如 50 首音乐）会 50 连问导致功能不可用，批量请求让默认策略保持"一次应答"的可用体验。

## Consequences

- 批状态由**宿主持有**：发送方直打接收方 HTTP 端点，宿主必须仲裁；批准后批内 session 创建不再调钩子。
- **ask 模式下强制批上下文防绕过**：上传 session 创建带可选批 ID，接收端策略为 ask 时无已批准批 ID 的 session 创建一律 403——防止直接打 `/upload` 绕过询问。两端插件同步升级，无兼容负担。
- 批准状态随批保留至批内全部 session 终态（+24h TTL 兜底），发送方断线重连续传免问；**等待同意期间断线不重发**，任务直接转 rejected（timeout）。
- 接收方任务（「正在接收」分类）只可取消、不可暂停/恢复；暂停/恢复仅限发起方。
- 移动端通知栏应答（接受全部/拒绝全部 action 按钮）需新增 Kotlin 能力（TaskNotificationManager 扩展 + PendingIntent 路由回插件命令），现有通知无按钮。
- 传输历史同时纳入范围（原 out of scope）：全部终态任务归档、封顶 200 条滚动淘汰、只读可清空。
