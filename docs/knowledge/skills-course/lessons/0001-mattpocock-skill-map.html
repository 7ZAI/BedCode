课 0001 · 全景图与主线流程

你装了 25+ 个 Matt Pocock 技能，但大多数活其实只走一条主线。这节课让你拿到任何场景都能把它放到这条线上、说出该调哪个技能。

一个心智模型：idea → ship

别去背 25 个技能。先记一条主线，再把少数几个旁路挂在上面。主线长这样：

grill-with-docs磨想法没代码库 → grill-me
→
to-spec固化 spec一次干完可跳过
→
to-tickets拆成票声明 blocking
→
implement每票一窗口内驱 tdd
→
code-review双轴评审再 commit

三条 on-ramp（旁路）处理后并入主线 implement：

  • /triage —— 别人提来的 raw issue 堆积，走 triage 角色机产出 agent-ready 票。
  • /diagnosing-bugs —— 难 bug（一眼看不出、间歇、回归），先建就红反馈环再修。
  • /wayfinder —— 巨型雾状工作、看不清路；产决策票不是交付，地图清了 handoff 到 to-spec。

上下文卫生（最容易踩的坑）：从 grill-with-docs 到 to-tickets 保持一个未中断的 context window，让磨想法/spec/票建立在同一套思考上；每张 implement 票开新窗口从 ticket 干。快满时阶段之间用内置 /compact，要 fork 用 /handoff。

记不住时

先调 /ask-matt —— 它是这套技能的路由器，会回主线+on-ramp 全景图告诉你下一步走哪。完整的"选哪个/何时别用/最佳用法"在速查表里：

→ 速查表：skill-selector.html（建议打印贴墙）

小练习：这个场景该调哪个？

下面 4 题各给一个 BedCode 真实场景，选出最该先调的技能。答案等长，别被格式套路。

1. 用户在 GitHub 给 BedCode 提了个 bug 报告，描述含糊，你还没看过代码。该先调？
2. 你自己想给 BedCode 加"终端标签拖拽排序"功能，想法还比较模糊。该先调？
3. BedCode 移动端 WebSocket 偶发断连，本地难复现，重启就好。该先调？
4. implement 干完一张票，提交前必做的最后一步是？

你今天拿到的

一条主线（idea → ship）+ 三条 on-ramp（triage / diagnosing-bugs / wayfinder）+ 一个路由器（ask-matt）。下次遇到活，先问"这是别人提的、难 bug、还是我自己的新想法"，然后对号入座。完整对照去翻 速查表。

推荐精读

ask-matt/SKILL.md —— 整套技能的地图原文，主线和 on-ramp 的权威出处。一遍读完就能自己复述这条线。

有不清楚的地方？直接问我（你的 agent 老师）。比如："为什么 triage 不能处理 to-tickets 自己产的票？" 或 "grill-with-docs 和 grill-me 到底啥区别？" —— 任何一题的反馈、速查表里某行、或主线哪一环都可以追问。
