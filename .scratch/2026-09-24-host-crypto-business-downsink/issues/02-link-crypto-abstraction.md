# 02: link_crypto 改走注册表抽象接口（WS 只留加密抽象层）

**What to build:** 把 WS/HTTP 加密过滤层（链路加密过滤器）与具体加密算法的直接耦合断开：原来它内联调用具体算法库，改为只依赖 `crypto/` 注册表的抽象接口。行为与字节输出必须完全不变，只是调用路径从「直接调算法」变成「经注册表按名调度」。这直接落实「WS 层面只留加密抽象层」——过滤层不再关心用的是 AES 还是 ChaCha，只声明要什么口径的加密，实现从注册表取。

**Blocked by:** 01

**Status:** done（2026-09-24 落地；cargo test 全量 1148 绿；生产数据面 AEAD/KDF/ECDH 全部经 crypto 注册表）

- [x] 链路加密过滤层对具体算法（AES-GCM 加密/解密、HKDF 派生、X25519 ECDH 计算）的调用改为经注册表抽象接口；生产路径已无直接 `utils::crypto::*` 算法调用
- [x] 既有链路加密单测全绿（32 项）；行为/字节不变
- [x] WS/HTTP 加密配置的通道子开关口径保持不变（opt-in 语义不受抽象化影响）
- [x] 说明：Kd 身份密钥对（`X25519KeyPair`）持久化保留直接引用——属密钥管理对象而非“按名选定算法”，不属于加解密抽象层（裁剪线内）
