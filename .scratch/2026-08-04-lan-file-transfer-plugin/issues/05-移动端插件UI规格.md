# 移动端插件 UI 规格

Type: prototype
Status: resolved
Blocked by: 02, 03

## Question

移动端文件传输插件的界面规格。依赖「宿主通用文件服务能力接口设计」。

已定框架：**工具箱内长条块状入口**（不放底部导航）→ 独立页面；双区布局（目录浏览 + 传输队列底部抽屉）；TailwindCSS + 宿主明暗主题；Material Design 语言；允许目录在插件设置区管理。

要敲定的：
- 工具箱入口块的内容（图标、名称、实时状态角标：N 个传输中？）
- 浏览面板：移动端文件列表交互（长按多选、滑动操作？）、面包屑回退、向本端上传的"发送到本机"入口
- 传输队列底部抽屉：展开/收起手势、任务行布局、失败重试
- 通知与后台：切后台后传输任务的行为（Android 限制下能做什么）、系统通知内容、回到 App 的状态呈现

设计输入（来自已决票据）：对端在线感知与任务状态推送走现有 WebSocket 控制面。
- 同名被拒提醒的弹窗形态（移动端 `context.dialogs`）

产出：低保真线框（/prototype）+ 交互说明，供用户过目后写入 spec。

## Answer

用户确认：**工具箱入口块（T）+ 页面方案 A（浏览为主 + 迷你传输条/底部抽屉）**。原型见 [prototypes/mobile-ui/index.html](../prototypes/mobile-ui/index.html)（`#T` / `#A` 直达；三变体完整稿为一次性原型，不进生产分支）。

### 入口块（工具箱内）

- 长条块状卡片：渐变圆角图标（⇄）+ 名称「文件传输」+ 副标题（对端名与用途）+ 右侧实时状态角标（如"2 传输中"，无任务时不显示或显示"已连接/离线"）。
- 不占底部导航；状态角标数据走现有 WS 控制面推送。

### 页面布局（方案 A）

- **顶栏**：返回 + 「文件传输」+ 对端名 + 在线绿点。
- **面包屑**：当前位置（共享目录 / 子目录）。
- **文件列表**：Material 列表项（类型图标 + 名称 + 大小/文件夹元信息 + 多选勾选框）；长按/勾选进入多选，底部出现主按钮「⬇ 下载到手机（N 项 · 总大小）」。
- **迷你传输条**（列表下方常驻）：当前任务方向图标 + 文件名 + 细进度条 + 实时速率；点击展开**底部抽屉**（bottom sheet，带抓手）：完整队列——任务卡含状态 chip（传输中/已暂停/失败/同名被拒）、进度、元信息、操作（暂停/恢复/取消、失败→重新排队）。

### 状态呈现与弹窗

- 四色 chip 体系与桌面端一致：传输中（绿）/ 暂停（琥珀）/ 失败（红）/ 同名被拒（紫）。
- 同名被拒：除队列内 chip 外，上传发起时即时弹 **Material 对话框**（采纳原型 C 中的样式）：标题"无法上传"+ 正文说明同名不可覆盖 + 单按钮"知道了"（`context.dialogs`）。
- 系统通知：全部完成/失败时经 `context.notifications` 推送（后台可见性细节归 Android 后台行为议题，见雾区）。

### 遗留（雾区，不阻塞）

- Android 切后台/锁屏时传输的存活方式（前台服务通知 or 接受中断依赖续传）未定，留待后续成票。
