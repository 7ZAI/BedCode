**公式来源（已用真实模型在 Windows 验证）**：参考文件在 `.scratch/ocr-plugin/ref/`（RapidOCR v2.x 源码 + v1.3 v4 配置 + `ref_pipeline.py` + golden json）。关键参数：det 736/min/round32/ImageNet(BGR)/thresh 0.3/box_thresh 0.5/unclip 1.6/use_dilation true；rec 6625 类（blank+6623+space）、max_wh_ratio 动态宽、pad -1；cls 48x192、180°>0.9；text_score 0.5 过滤。模型输出 sigmoid/softmax 已内嵌，后处理不再算。`ref_pipeline.py` 在 Windows 用真实三模型跑通 4 行合成样张（中/英/混排 100% 识别），公式正确性已验证。

**cv2 移植坑（已实测校准）**：fillPoly 是整数 y 扫描线 + 闭区间 [round(x0),round(x1)]（不是像素中心判定）；dilate 2x2 anchor(1,1) 即右下扩展（越界 0）；np.round/round() = round-half-even（Rust `round_ties_even`）；polygon_offset 凸角圆弧方向用 point-in-polygon 判据选外角弧（"距中心更远"判据对角落顶点失效）。

**RapidOCR 一个已知怪癖**：`sorted_boxes` 只排序 boxes 不同步 scores（golden_scores 与 golden_boxes 错位）；Rust 实现 score 跟随 quad（更正确），golden 测试仅断言 boxes 坐标 ±2px。

**验证现状**：Windows `cargo test` 全量 359 通过（ocr 58 个新测试含 golden 对比）；Android `cargo build --target aarch64-linux-android --lib` 通过（libbedcode_lib.so 175MB debug）。NDK env 备忘：`ANDROID_NDK_HOME` 必须指向 `ndk/30.0.14904198/toolchains/llvm/prebuilt/windows-x86_64`（r30 的 clang.exe 与 sysroot 都在其下，指向 NDK 根会让 cc-rs 探测到不存在的顶层 sysroot 而报 string.h not found）。
