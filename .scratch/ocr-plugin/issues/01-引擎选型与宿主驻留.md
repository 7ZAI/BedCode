# 引擎选型与宿主驻留

Label: wayfinder:issue
Type: grilling
Status: resolved

## 决策

OCR 引擎 = **宿主原生 Rust 实现**（PaddleOCR PP-OCRv4 ONNX 模型 + `ort` onnxruntime 运行时），位于 `bedcode-mobile/src-tauri/src/ocr/`；移动端 OCR 插件为薄 WASM 壳（取图 UI + 结果展示 + 模型管理），经宿主命令调用引擎。引擎随 App 发版演进，不随插件 zip 分发。

## 背景事实（勘察核实）

- 移动端插件后端是 WASM（wasm32-unknown-unknown）：无多线程、内存受限，onnxruntime 不支持该目标。
- **ocrs**（纯 Rust 最强 OCR）：官方 README 明示 *"currently recognizes the Latin alphabet only (eg. English)"*，中文需自训模型（研究级工作量）。→ 中文 v1 直接出局。
- **Tesseract**（Rust 绑定）：中文可跑但精度显著落后 PaddleOCR；需 NDK 编译 leptonica+tesseract C++ 库，构建负担重。
- **PaddleOCR PP-OCRv4**（开源中文 OCR 精度标杆）：官方无 Rust API，但 ONNX 模型 + Rust `ort` 运行时是成熟路径（PP-OCRv4 模型 det 4.7MB + cls 1.3MB + rec 中文 10.9MB，适合移动端；Apache-2.0）。

## 取舍

WASM 插件自包含分发性（可热更新 zip）vs 中文识别精度 + 引擎可维护性。中文是 v1 刚需，选后者。代价：引擎升级跟 App 发版走；「OCR 插件」实质是「宿主 OCR 能力 + 插件 UI 壳」。
