# 04 — 移动端事件 WS：HTTP 认证成功后常驻 + 自动重连

**What to build:** HTTP 认证成功后（03 取得 JWT），移动端 Rust **立即建立并保持一条事件 WS 连接**：连接建立后首消息发 JWT 认证（§4.3「首消息 JWT 认证」规则），认证通过后专用于接收桌面端所有通知与同步事件（SyncData/会话生命周期/文件服务消息/ServerClosed 等）；**常驻不主动断开**；意外中断按**现有重连规则**自动重连（现有 ws_client/ConnectionManager 的退避规则：500ms→1s→2s→4s→8s 封顶），每次重连成功后重发认证消息；认证失败判定为 token 失效时，先经 HTTP `reauth` 换发新 token 再重连。

**该连接只用于接收通知与同步事件；PTY 输出订阅走另一条连接**（前端终端 WS，ticket 10）——终端 I/O 不在本连接上。

删除常驻主 WS 中已迁移职责：认证握手（HTTP 承担）、终端 I/O（前端 WS 承担）。**设备在线语义由本条事件 WS 存活判定**（用户定稿，D8）：注册表 channel_type=Event 且已认证即在线，最后一条事件 WS 断开触发离线（见 01）。
