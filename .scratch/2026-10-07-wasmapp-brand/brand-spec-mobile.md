# WasmApp 移动端品牌规范

> 状态：移动端适配层（2026-10-08）
> 上游真源：`../brand-spec.md`（品牌策略 / 标志构造 / 命名裁决）+ `../assets/wasmapp-mark.svg`（标志几何）
> 本文件只定义**移动端**的落地规则，不重复上游的品牌策略
> 资产：`./svg/`、`./png/`；生成器：`./build-assets.py`

---

## 0. 这份文件解决什么

桌面品牌规范把标志、色板、字体都定了。移动端有三件事它没覆盖，而这三件事都会让落地跑偏：

1. **应用图标**。桌面只有 favicon 和 in-app mark；手机要 16 / 24 / 32 / 48 / 512 / 1024 六档，还要 iOS 圆角方形与 Android 自适应图标两套画布。
2. **小尺寸降级**。现有标志在 16px 与 24px 上会糊成一团（下有实测），必须给一版主动简化的资产，而不是让它自然劣化。
3. **品牌色与平台色板的关系**。移动端有 5 档用户可切换主色板（象牙白 / 森绿 / 海蓝 / 落日橙 / 紫罗兰），琥珀必须有一个明确位置，否则要么被色板吃掉、要么和 UI 抢色。

---

## 1. 双色层架构（本次最重要的裁决）

**品牌琥珀固定，不跟平台色板走。** 两者分属不同层，永不互相覆盖：

| 层 | 取值 | 出现在哪 | 谁决定 |
| --- | --- | --- | --- |
| **品牌层** | 固定琥珀 `#FF9E2C` | 标志、启动页、关于页、商店素材、应用图标 | 品牌（不可配置） |
| **UI 层** | 用户色板 `--mobile-accent` | 按钮、开关、选中态、链接、进度条 | 用户在「外观」里切换 |

这条与 `../brand-spec.md` §6「琥珀是系统锚点，不是可调参数」一致，只是把它落到移动端的具体冲突出处：**用户把主色换成海蓝时，标志仍然是琥珀**，因为标志不是 UI 控件。

落地约束：

- 品牌琥珀不得写成 `--mobile-accent` 的别名，也不得进 `data-palette` 的覆盖范围。
- 同一个屏幕里，琥珀与用户主色可以同时出现，但**琥珀只能出现在品牌位**（标志 / 品牌名 / 品牌说明），不得用于可点击控件。
- 若某个界面同时有品牌琥珀与用户主色且显得吵，**去掉琥珀的 UI 用法，保留标志**，不要反过来动标志。

## 2. 颜色

### 2.1 品牌色阶

| 名称 | 值 | 用途 |
| --- | --- | --- |
| `ember` | `#FF9E2C` | 深底上的唯一彩色。标志核心、启动页、深色应用图标 |
| `ember-700` | `#9F621B` | 浅底上的琥珀。浅色图标核心、浅底品牌文字（12px 以上） |
| `ember-800` | `#764914` | 浅底上的长文案 / 小字（AAA） |
| `ink` | `#08090B` | 主深底（品牌物料，非 UI） |
| `ink-2` | `#16181C` | 抬升面 / 图标底板上端 |
| `ink-3` | `#101216` | 小尺寸图标底（更平，避免渐变在 16px 产生噪点） |
| `paper` | `#F5F7F9` | 主前景 / 标志笔画 |

新增 `ember-700` / `ember-800` 的原因：`#FF9E2C` 在移动端**浅色主题**下只有 1.87:1，完全不可用。上游规范只给了深色场景，移动端必须补浅色档。

### 2.2 实测对比度矩阵

深色底（要求：文字 ≥4.5:1，图形 ≥3:1）

| 前景 | bg-primary 15130F | bg-secondary 191712 | bg-card 1D1A15 | bg-elevated 2A261E | bg-tertiary 3C372B |
| --- | --- | --- | --- | --- | --- |
| `ember` #FF9E2C | 8.99 | 8.68 | 8.41 | 7.30 | 5.74 |
| `paper` #F5F7F9 | 17.28 | 16.68 | 16.15 | 14.02 | 11.03 |
| `ink-2` #16181C | 1.04 | 1.01 | 1.02 | 1.18 | 1.50 |

浅色底

| 前景 | bg-page F5F4F0 | bg-secondary EFEDE7 | bg-card FDFCFA | bg-elevated E7E4DC |
| --- | --- | --- | --- | --- |
| `ember` #FF9E2C | 1.87 | 1.76 | 2.01 | 1.62 |
| `ember-700` #9F621B | 4.50 | 4.23 | 4.83 | 3.90 |
| `ember-800` #764914 | 6.98 | 6.56 | 7.49 | 6.05 |
| `ink-2` #16181C | 16.15 | 15.18 | 17.33 | 13.99 |
| `paper` #F5F7F9 | 1.02 | 1.09 | 1.05 | 1.18 |

**规则（照这张表取色，不要凭感觉）**

1. 深底 → 一律 `ember`。任何深色移动端表面都 ≥5.74:1。
2. 浅底文字 → `ember-700`，且只在 `bg-page`（4.50）与 `bg-card`（4.83）上；`bg-secondary`（4.23）与 `bg-elevated`（3.90）不够，改用 `ember-800`。
3. 浅底图形（图标、描边、指示条）→ `ember-700` 即可，最低 3.90:1，仍 ≥3:1。
4. **`ember` 绝不出现在浅底上。** 1.87:1 不是「有点淡」，是不可见。

### 2.3 与移动端 UI token 的边界

品牌色**不写进** `mobile.css` 的 token 表。移动端 token 是 UI 语义层，品牌色是品牌层；混在一起会让「用户换色板」和「品牌换色」两件事互相污染。品牌色在落地代码里单独一处声明（例如 `src/brand.ts` 导出常量），由品牌位直接引用。

## 3. 标志

### 3.1 构造（不变）

四段分离笔画 + 中心琥珀菱形。语义与上游一致：

| 元素 | 对应 |
| --- | --- |
| 四段分离的 W 笔画 | 多个 WASM 应用，各自隔离 |
| 笔画之间的接缝 | 隔离边界（插件间只经互调 API 与 host-bus） |
| 琥珀核心菱形 | 正在运行的那个活跃实例 |
| 圆角方形容器 | 宿主沙箱边界 |

几何真源在 `build-assets.py` 的 `MASTER_SEGS` / `MASTER_CORE`，与 `../assets/wasmapp-mark.svg` 逐值一致。标志视觉外框 66.6 × 47.1，中心 (50, 50)。

### 3.2 小尺寸降级（新增，**必须遵守**）

现有标志在 32px 以下会糊。实测（把同一张图放大 12 倍用最近邻看）：

| 尺寸 | 现状 | 结论 |
| --- | --- | --- |
| 16px | 四段笔画糊成一条白带，琥珀核糊成一块米黄 | 不可用 |
| 24px | 接缝勉强可见，琥珀核已变形 | 勉强 |
| 32px | 接缝可见，核清晰 | 可用 |
| ≥48px | 完整标志成立 | 用标准版 |

因此规定：

| 尺寸 | 用哪个资产 | 形态 |
| --- | --- | --- |
| 16 / 24 / 32px | `app-icon-compact-*` | 笔画**合并为单条折线** + 方形核心。外轮廓与 W 字形和标准版完全一致，只是不再分段 |
| ≥48px | `app-icon-ios` / `app-icon-48` | 完整四段标志 + 菱形核心 |

合并版仍保留琥珀核心，让「活跃实例」的语义在小尺寸下不丢。这是**主动简化**，不是劣化：接缝在 32px 以下本来就读不出来，与其让它糊，不如给一个干净的粗笔画版本。

三档笔画是实测选出来的（渲染 2.4 / 2.9 / 3.2 / 4 / 4.5 / 5 / 6 / 13 / 15 / 16.6 十档，按 16px 墨迹覆盖率与字形可辨性取最优）：

| 尺寸 | stroke（0-100 坐标） | 实际渲染笔画 | 墨迹覆盖率 |
| --- | --- | --- | --- |
| 16px | 16.6 | 2.66px | 18.8% |
| 24px | 15.0 | 3.60px | 17.0% |
| 32px | 13.5 | 4.32px | 15.6% |

### 3.3 图标画布

| 平台 | 画布 | 圆角 | 标志占宽 |
| --- | --- | --- | --- |
| iOS / App Store | 1024×1024 | 22.37%（Apple 超椭圆近视值） | 62% |
| Android 自适应前景 | 108dp，内容限制在居中 66dp 安全区 | 不画圆角，系统遮罩 | 48dp（安全区 73%、可见区 67%） |
| Android 自适应背景 | 108dp 满幅渐变 | 不适用 | 不适用 |
| Android 单色层 | 108dp，纯白轮廓 | 不适用 | 同前景 |

Android 自适应图标常见错误是把内容画到安全区外，被各种遮罩裁掉。前景层 `app-icon-adaptive-foreground.svg` 已按 66dp 安全区约束。

### 3.4 最小尺寸与降级

| 场景 | 尺寸 | 资产 |
| --- | --- | --- |
| 应用网格 | 48 到 192 | `app-icon-ios.svg` |
| 通知栏 / 列表小图标 | 24 / 32 | `app-icon-compact-24 / 32` |
| 浏览器 favicon | 16 / 32 | `app-icon-compact-16 / 32` |
| 单色印刷 / 水印 | 任意 | `icon-mono-paper` / `icon-mono-ink` |
| 顶栏 / 商店标题 | 高 28-40 | `lockup-compact.svg` |

标志四周最小留白 = 核心菱形对角线长度的 1/2（沿用上游规则）。

## 4. 字体（移动端）

上游给的是「几何无衬线 + 等宽」，移动端需要可落地到 CSS 的取值：

| 角色 | 取值 | 说明 |
| --- | --- | --- |
| 品牌字标 | 无衬线 700，字距 -1.2 | 与移动端 UI 字体栈同源，不额外引入 webfont |
| UI 正文 | `--font-size-*` 流式 token | 移动端既有系统，品牌不另立字号 |
| 等宽 | `ui-monospace` / JetBrains Mono | ABI 版本、组件 ID、capability 名 |

**品牌字标在移动端只出现在顶栏、关于页、启动页**，不进入列表与卡片。顶栏空间有限，字标用 `lockup-compact.svg`（约 120px 宽），不要塞完整锁定组合。

字标配色：`Wasm` 用 `paper`（深底）或 `ink-2`（浅底），`App` 用 `ember`（深底）或 `ember-700`（浅底）。

## 6. 应用规则

**禁止**

- 改变琥珀色相（`ember` 是品牌锚点，不是可调参数）。
- 在浅底上使用 `ember` `#FF9E2C`。
- 给四段笔画加圆角端帽（破坏构造几何）。
- 旋转、拉伸、非等比缩放标志。
- 给标志加投影、外发光、渐变描边。
- 小尺寸强行用完整标志（32px 以下用 `compact`）。
- 把品牌琥珀当作 UI 控件色。

**允许**

- 深底 ↔ 浅底换用 `mark` / `mark-light`（这是同一标志的两套明度，不是两个标志）。
- 单色场景用 `mark-ember` / `icon-mono-*`。
- 启动页把标志放大到 `launch-mark`（134%）。

## 7. 已知待决

1. **命名落地**。`../brand-spec.md` §1 指出 BedCode → WasmApp 是**定位升级**，不只是换标签：README、`tauri.conf` 的 `shortDescription`、商店文案都要同步重写，否则会出现「名字说平台、内容说终端」的割裂。本规范假设迁移会发生，但**没有改任何产品代码**。
2. **移动端原型里的品牌位**。`../../2026-10-07-mobile-wasm-platform/prototype.html` 首页顶栏目前写的是 `BedCode`，应改为 `WasmApp` 并接入 `lockup-compact`。这属于原型改动，等命名裁决后再一起做。
3. **浅色主题下的应用图标**。移动端支持浅色主题，但应用图标通常是固定图片。本规范提供了 `app-icon-light.svg` 备用；是否随系统主题切换由平台决定，不作为默认行为。

## 8. 复现

```bash
cd .scratch/2026-10-07-wasmapp-brand/mobile
python3 build-assets.py          # 只生成 SVG
python3 build-assets.py --png    # 同时导出 PNG（需要 rsvg-convert）
```

改标志只需改 `build-assets.py` 的 `MASTER_SEGS` / `MASTER_CORE`，所有资产会一起更新，不会出现「大致像」的平行版本。
