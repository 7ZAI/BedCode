### 过程发现与决策（新会话勿重复踩坑，03/09 参考）

1. **跨 Engine 实例化被 wasmtime 拒绝**：“cross-Engine instantiation is not currently supported”——组件必须与引擎同一实例编译（生产路径 compile+instantiate 共用 `self.engine` 天然满足；测试用新增 `engine()` 访问器）
2. **LLVM 消除假象**：guest 的 `vec![0u8; 300MB]`/`with_capacity` + 仅读首字节，因 wasm 内存初始即零被整体消除——**不触发 memory.grow、limiter 不被调**（安全基线仍成立：显式 `memory.grow(4800 页)` 被 limiter 拒绝实证）。组件测试用显式 `core::arch::wasm32::memory_grow` 观测
3. **`tauri::test::mock_builder` 与生产类型不兼容**：产出 `AppHandle<MockRuntime>`，生产（Wry）用不了；`Builder<Wry>::build` 在测试线程触发 tao 事件循环 panic → 采用桌面端同款「app_handle Option 化（无头降级）」方案，测试传 None
4. **AOT 缓存边界**：源文件消失时缓存不命中（新鲜度判定依赖源 mtime，源缺失按不新鲜）——与 core `Module` 路径同款逻辑，09 归一化时如需改进统一处理
5. **既有环境依赖测试缺陷**（非本次引入，顺手加保护）：`test_sweep_batches_timeout_and_cleanup` 用 `Instant::checked_sub(24h)` 构造旧时间——Windows 单调时钟自开机起算，开机 <24h 的机器上必挂；已改为 uptime 不足时跳过 approved 分支（pending 路径仍验证）
