## Notes

**领域**：BedCode 插件系统（TS 前端 + WASM Rust 后端，两端同构）；内网 WiFi 手机 ↔ PC 双向文件传输。
**应咨询的 skill**：`/grilling`、`/domain-modeling`、`/prototype`（UI 票据）、`/research`（调研票据）。

**宿主现状事实**（charting 时勘察）：
- 插件后端是 WASM 沙箱：不能直接开 TCP socket；出站 HTTP 走宿主代理（`network:http` / `host_http_fetch`）；文件访问走 `fs:read`/`fs:write` 授权弹窗；另有 storage、消息总线、UI 扩展点（toolbox/navTab/设置区）。
- 桌面端宿主已有 actix HTTP server：JWT 中间件、配对码、QR 连接、file-tree 等路由齐全。移动端宿主无任何对外 server。
- 插件开发文档：`docs/plugin-dev-mobile.md`；权限表、清单格式见其中第 5–6 节。

**已锁定共识**（charting grilling 结论）：
1. 访问语义：允许浏览/下载/上传（新建文件）；**禁止删除、重命名、移动、覆盖**——目标目录已存在同名文件时上传被拒并提醒，不自动避让。
2. 拓扑：**对称双向**——两端各自运行文件服务，任一端可发起。一切基于已建立的配对连接。
3. 发现机制：**out of scope**（复用现有配对，不做 mDNS）。
4. 认证：**完全复用宿主连接与认证**（桌面端挂现有 actix server + JWT 中间件），不新开认证体系、不额外认证、不独立端口。
5. 性能：文件大小不设上限（几十 GB 级）；流式传输，拒绝整文件内存加载；目标打满 WiFi 链路；并发传输数可配置、有默认值；无其他硬性指标。
6. 宿主扩展分工：**宿主出"通用受控文件服务"能力**（流式 IO、Range/续传、JWT、目录越界防护，数据不经 WASM），插件只声明配置（挂载路径 + 允许目录根 + 操作白名单）+ 策略钩子（如"同名即拒"上传前校验）+ 全部 UI。该能力设计为通用接口，文件传输插件是第一个消费者。
7. 协议候选集：① HTTP/1.1 + Range（主候选）② HTTP/2 ③ QUIC（对照）；FTP 已排除（与连接复用/单端口/JWT 冲突）。
8. 传输体验：任务列表（进度/速率/剩余时间）+ 暂停/继续/取消 + 队列 + 断线自动转"暂停-待续传"、偏移持久化在插件 storage + 完成/失败系统通知；不做限速、定时、历史长期留存。
9. UI：目录浏览面板 + 传输队列抽屉双区布局；TailwindCSS + 宿主明暗主题；**移动端入口放工具箱（长条块状入口），不放底部导航**；桌面端信息密度更高（表格/右键菜单）；允许目录在插件设置区管理，选目录走宿主 fs 授权弹窗；状态清晰优先，不做花哨动效。

## Decisions so far

- [传输协议选型](issues/01-传输协议选型.md) — HTTP/1.1 + Range（用户已拍板）：下载用原生 Range，上传用 session 式续传（创建时同名校验 → 偏移 append → 完成改名）；MVP 不做文件内分片；并发默认 3 可配置。
- [宿主通用文件服务能力接口设计](issues/02-宿主通用文件服务能力接口设计.md) — 运行时挂载 API（`context.fileService.mount`）+ 单钩子 fail-closed + canonicalize 沙箱；两端各自实现（不建共享 crate）；移动端服务认证用已认证 WS 引导的 Bearer Token；控制面消息走现有 WS。
- [断点续传与任务持久化方案](issues/03-断点续传与任务持久化方案.md) — 8 态状态机；重连自动续传/重启后手动恢复；storage 节流持久化 + 状态迁移立写；指纹不匹配即 failed、session 丢失自动重建；临时文件同目录 `.part` + 原子改名，三路清理兑底。
- [桌面端插件 UI 规格](issues/04-桌面端插件UI规格.md) — 选定 Variant A 双栏工作台：左目录表格（多选）+ 右常驻传输队列（状态汇总 chips + 任务卡）；四色状态标签体系。原型：prototypes/desktop-ui/index.html#A。
- [移动端插件 UI 规格](issues/05-移动端插件UI规格.md) — 工具箱长条入口块（实时状态角标）+ 页面方案 A：浏览为主 + 迷你传输条/底部抽屉队列；同名被拒用 Material 对话框即时提醒。原型：prototypes/mobile-ui/index.html#A。
- [用户授权流与安全细节](issues/06-用户授权流与安全细节.md) — 白名单默认空即默认安全；配对+白名单即完整信任模型；不做审计；明文告知一行文案 + **传输层加密拦截预留缝（MVP 空实现）**；同名被拒仅发起方感知，四条 i18n 文案定稿。

**实现期收尾定案**（用户直接拍板，不再成票，已并入 spec 第 12 节）：
- 桌面端入口：侧边栏菜单新增一项（桌面 SDK SidebarPanelDescriptor）。
- Android 后台：尽最大努力存活（Android 允许的保活机制，如前台服务通知）+ 接受中断 + 依赖断点续传兑底。
- 插件分发：内置（移动 APK assets + 桌面内置资源，与 ai-chatbox/auto-task 同级）+ 保留 zip 安装通道供独立更新。
- 性能验收基准：iperf3 定分母（T）+ 磁盘测速（D），五项验收（单大文件 ≥80%×min(T,D)、并发 ≥75%、三段中断续传哈希一致、无僵尸任务、内存增长 ≤100MB）。
- 插件 id：两端同名 `com.bedcode.file-transfer`。

## Out of scope

- **对端发现（mDNS/广播）**：一切基于已建立的配对连接，用户明确不再处理发现问题。
- **覆盖/重命名/移动/删除远端文件**：访问语义已锁死为"只可放入与取出"。
- **独立认证体系 / 独立传输端口**：已决定完全复用宿主 server 与 JWT。
- **限速、定时传输、传输历史长期留存**：体验范围已排除。
- **跨外网/远程传输**：目的地限定内网 WiFi 场景。
- **端到端加密的实际实现**：本期只预留传输层加密拦截缝（空实现）；真正的 X25519 + AES-GCM 接入属宿主远期计划，另起努力。
- **访问审计日志**：用户明确 MVP 不做；若未来需要，作为宿主通用能力扩展项另起努力。
