# 接收策略与批量批准协议（v2 增补）

Type: grilling
Status: resolved

## Question

双端文件传输插件没有"被推送"的概念：对端上传时接收端零感知（仅宿主同步钩子 allow/deny，2s 超时 fail-closed），队列只存在于发起方。要求：接收端有「正在接收」概念（toast 提醒 + 队列分类 + 可取消/拒绝），插件配置增加接收策略（每次询问 / 直接接收），每次询问时上传方必须经同意才能开始传输。本票定策略语义、协议层异步批准机制与边界处理。

## Answer

经逐项 grilling 敲定如下（用户确认）：

### 1. 接收策略（插件配置，全局单开关）

| 字段 | 类型 | 取值 | 默认 |
|---|---|---|---|
| `receivingPolicy` | enum | `ask` 每次询问 / `accept` 直接接收 / `reject` 直接拒绝 | `ask` |
| `approvalTimeoutSec` | number | 10–600，仅 `ask` 生效 | `60` |

- 与 `roots / download_dir / concurrency` 并列存插件 storage，设置区新增 UI（自绘控件，禁原生 select；超时输入仅策略为每次询问时显示）。
- 接收端本地生效，发送方不感知（发起请求一律发，接收端钩子分流）；`reject` → 403 无任务无记录、`accept` → 直接放行、`ask` → pending 批。

### 2. 协议：异步批准流（推翻 v1 同步钩子，见 ADR 0016）

- 钩子三路化：`allow / deny / ask`。新增批级钩子 `onTransferRequest(meta: { batchId, files: [{relativePath, size}], totalSize })`；per-file `onUploadRequest` 保留（accept/reject 路径）。
- 新端点 `POST /transfer-request`：钩子按策略分流 → `allow` 直接批准返回批状态；`ask` 批进入 pending（202）；`deny` 403。
- 批准/拒绝 = 接收端**本地宿主命令**（approve/reject transfer request，非 HTTP 端点）：用户应答 → 插件调宿主命令 → 批状态迁移 → WS 控制面推送发送端 → 发送方任务转「传输中」/「被拒绝」。
- **上传拆两段**：先询问同意，批准后才开始数据流；批准后批内文件 session 创建**免钩子**（宿主持有批状态）。
- **ask 模式强制批上下文**：session 创建带可选批 ID，ask 策略下无已批准批 ID 的 session 创建一律 403（防绕过 `/upload`）。
- pending 批 TTL 扫描在宿主，超时自动拒绝。

### 3. 状态机

**发送方（上传）**：`queued → waiting-approval（等待对方同意，仅 ask 模式）→ transferring → completed / failed / paused / resumable`；`waiting-approval → rejected（对方拒绝/超时）/ cancelled（自己取消）`。
**接收方（新增任务记录）**：`pending（批，仅 ask 模式）→（批准后文件逐条）transferring → completed / failed`；`pending → rejected（用户拒绝/超时）`；`transferring → rejected（用户中途取消）`。

- rejected 的 reason 扩展枚举：`duplicate-name`（已有）/ `user-rejected` / `timeout` / `policy-denied`。
- 发送方区分三种拒绝文案：对方拒绝 / 对方未响应（超时）/ 对方策略拒绝。
- **接收方只能取消、不能暂停/恢复**；暂停/恢复仅限发起方。
- 接收方任务不跨重启持久化（宿主孤儿清理兜底，发送方 session 丢失自动重建从头传，与 v1 一致）。

### 4. 边界处理（用户逐条确认）

1. 等待同意时断线：**不重发、不幂等重试**，任务直接转 `rejected (timeout)`；接收端 pending 批自然超时消失。
2. 批准后断线：批准状态随批保留至**批内全部 session 终态**（+24h TTL 兜底，复用 session TTL），重连续传**免问**。
3. 接收端重启：pending 批不跨重启，发送方超时 rejected。
4. 多对端并发请求：批独立、各自应答、各自超时。
5. 批内文件同名：沿用 v1 per-file 创建时同名即拒，该文件 rejected，批内其他不受影响。

## Out of scope（本票）

- 逐文件选择（「逐个选择」应答）：用户明确砍掉，仅 接受全部 / 拒绝全部。
- 接收策略按对端记忆（per-peer）：全局单开关，v2 不做。
- 静默拒绝模式（`reject`）下的任务记录：不建任务不记录（零打扰原则）。
