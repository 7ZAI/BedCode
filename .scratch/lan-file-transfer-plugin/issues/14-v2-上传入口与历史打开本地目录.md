## 需求 1：上传功能入口常驻

**现状问题**：V2 把上传入口收进底栏 upload 态（`FileTransferViewV2.vue` `footerMode`：select > active > upload 三态互斥）。有活跃传输或勾选时底栏被占用，**全局无上传入口**。旧版在顶栏常驻「上传文件」按钮（`transfer.topbar.uploadFile`），V2 相对旧版是体验回退。

**方案（推荐 A）**：PeerHeader（`v2/components/PeerHeader.vue`）行尾弹性空隙后、设置齿轮旁加一个上传 icon 按钮（复用 `.fv2-icon-btn` 44px 模式），点击走现有 `uploadFile()`（`file-transfer.pick-files` → `file-transfer.enqueue`）。底栏三态语义不变（空闲态仍显示大 CTA）。对端离线时置灰。

- 涉及文件：`PeerHeader.vue`（结构）、`FileTransferViewV2.vue`（传事件）、`styles.css`（如需）
- 无 i18n 新增（可用现有 `transfer.v2.upload.cta` 或加 title）

## 需求 2：历史记录「点击打开本地目录」

**用户诉求**：历史传输记录中「接收/下载到本机」的条目，点击能打开本地目录。

**现状调研结论**：

- ✅ **宿主能力已就绪**：
  - `src-tauri/src/plugin/android_plugins/downloads.rs`：`open_download_file_location(path)`（历史记录「打开所在文件夹」专用，Kotlin `DownloadsDirPlugin.openFileLocation` = FileProvider 暴露父目录 + ACTION_VIEW）
  - SDK：`context.files.revealInDir(path)` / `openFile(path)`（需 `system:open` 权限：`system.openFile` / `system.revealInDir`，permission.ts 已登记）
- ❌ **数据链路缺口**：
  - `TransferEntry`（`plugins/file-transfer/rust/src/transfer_store.rs`）**无 localPath 字段**：wire 只有 `batch_id/node_id/peer_name/direction/status/files/total_bytes/transferred_bytes/rate_bps/detail/reject_reason/created/updated/retry_meta`
  - `mapWireHistory`（`composables/useTasks.ts`）硬编码 `localPath: null`
  - `HistoryEntry.localPath`（`types.ts:192`）注释「仅 completed 且本地有文件时非空；**移动接收任务恒缺**」

**实施计划（5 步）**：

1. **WASM 后端**：`TransferEntry` 加 `local_path: Option<String>`（仅 receive + completed 归档时记录落盘路径）。⏳ 待验证：引擎 `peer:receive` DTO 是否携带本地路径；不带则从 `RetryMeta.Pull` / 下载目录解析链（`resolve_app_downloads_dir` 同链）推导。并行补 Rust 单测。
2. **前端 wire**：`mapWireHistory` 映射 `raw.localPath`（去掉硬编码 null）；类型保持 `localPath?: string | null`
3. **V2 历史卡**：completed + download 方向且有 `localPath` 的条目显示「打开所在文件夹」操作 → `context.files.revealInDir(localPath)`；无 localPath 的禁用/隐藏；失败/取消/发送方向不显示
4. **演示闭环**：devMock `transfer.tasks.history` 补 `localPath`；dev-shell mock 注册 `revealInDir` 骨架命令（通用接线，read-only 日志）
5. **权限**：确认插件声明 `system:open`；收尾 `pnpm run test:run` + 截图 + vision 复查

**风险**：接收文件可能落 MediaStore 公共下载（content:// 场景），FileProvider 暴露父目录的路径语义需实测核对（DownloadsDirPlugin.kt 已有「MediaStore 命中优先，未命中 FileProvider」双轨，风险可控）。

## 实施结果（2026-09-05 会话内完成）

- **需求 1（上传入口常驻）**：PeerHeader 行尾新增 accent 上传 icon 按钮（`.fv2-icon-btn--accent`，44px，对端离线置灰），与底栏空闲态 CTA 共用 `uploadFile()`。vision 确认无挤压/错位。
- **需求 2（历史打开本地目录，第 1-4 步）**：
  - `TransferEntry.local_path`（wire camelCase `localPath`）+ `from_dto` 映射 + peer.rs 字面量补字段；`mapWireHistory` 映射 `raw.localPath`（不再硬编码 null）
  - V2 历史卡：仅 completed+receive 且有 localPath 显示「打开所在文件夹」（tint）→ `context.system.revealInDir(localPath)`（宿主 FileProvider 暴露父目录 + ACTION_VIEW）
  - devMock 完成条目补 localPath 驱动演示；i18n zh/en/messages 同步（openFolder / noLocalFile）
  - 验证：插件 Rust `cargo test` 20/20、前端 `pnpm run test:run` 315/315、vision 视觉核验双通过
- **需求 3（滑动手势，auto-task 模式）**：内容区声明 `data-swipe-zone` + `data-zone-at-start/end`（宿主 MobileSwipeContainer 仲裁，边界交还外层翻页）；新增鼠标指针拖动回退（dev-shell/桌面预览可测，真机触摸同语义不双触发）。CDP 鼠标拖拽探针实测 传输→浏览 切换成功。
- **⚠️ 真实设备落地缺口（宿主 DTO 扩展，后续排期）**：移动端引擎 `peer:receive` / `peer-receive-changed` 的 `PeerTransferDto`（`src-tauri/src/peer_transfer.rs`、`peer_receive.rs`）**无本地路径字段**；引擎 `TransferEvent`（`packages/peer-net/src/transfer.rs`）的 OfferPending/Progress/Terminal 亦不含落盘路径。接收文件经 MediaLanding 落 app 私有下载目录并尽力提升 MediaStore 公共下载（私有副本删除）。因此真实设备上 `localPath` 当前恒为 null，历史卡不显示打开按钮。落地需：宿主在接收 Terminal 时按落点推导 localPath 写入 DTO（或新增 MediaStore 按名解析的「打开所在文件夹」Kotlin 命令，参考现有 `openFile` 的 displayName 命中逻辑），并给 file-transfer 插件授予 `system:open` 权限。dev-shell 演示链路已完整（mock 的 revealInDir 打日志）。
