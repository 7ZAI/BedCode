# 传输历史与队列分类（v2 增补）

Type: grilling
Status: resolved

## Question

接收端引入「正在接收」概念（用户原话：toast 提醒「xx 正在向你上传 xxx 文件」+ 队列「正在接受」分类 + 可取消/拒绝）。同时原 spec out of scope 的「传输历史长期留存」纳入范围（用户追加：传输记忆/传输历史记录）。本票定领域术语、队列分类结构、提示呈现形态与历史记录模型。

## Answer

经逐项 grilling 敲定如下（用户确认）：

### 1. 术语与分类（已入 CONTEXT.md）

- **发送 / 接收**：以**发起方**区分（非协议方向）。发送 = 我发起的传输；接收 = 对端发起的传输。上传/下载保留为协议层方向词。
- 队列分类 tabs：**全部 | 正在发送 | 正在接收 | 历史**（四个）。
- 「接受」一律改称「接收」（用户定稿），接收策略同理。

### 2. 提示呈现形态

- **批量请求应答**：移动端前台 = 应用内对话框、后台/锁屏 = 系统通知带 action 按钮（接受全部 / 拒绝全部）；桌面端 = 应用内横幅，最小化时系统通知仅「打开应用」（不直接应答）。**无「逐个选择」**（用户砍掉）。
- **接收中 toast**「xx 正在向你上传 N 个文件」：ask 模式 = 同意后批级一条；accept 模式 = 传输开始时发，**3 秒窗口合并去重**（窗口内新文件启动只更新计数）；reject 模式无 toast。
- 传输中持续状态走「正在接收」tab（移动端另有前台服务通知带取消动作，复用现有 TaskNotification 机制）。
- 待同意批 = 一张 pending 卡片（对端名 + N 个文件 + 总大小 + 接受全部/拒绝全部）；批准后批卡片消失、文件逐条出现；拒绝/超时后批卡片消失且**接收方不记历史**（发送方侧 rejected 记录足够）。

### 3. 传输历史（v2 纳入，原 out of scope）

- **记录范围**：两端各自的全部终态任务（发送 + 接收、完成/失败/被拒/取消）一视同仁；终态即归档进历史存储（替代「重启清除」）。直接拒绝模式无任务记录可记，不补记。
- **保留策略**：封顶 **200 条**、超出滚动淘汰最旧（插件 storage JSON）。
- **UI**：队列第四 tab「历史」，条目只读（时间、方向 ↑/↓、文件名、大小、结果），提供「清空历史」；不做单条删除。
- **打开所在文件夹**：已完成且有本地文件的任务提供入口——桌面 `context.system.revealInDir`（定位文件）、移动复用现有「系统查看器打开文件」（MediaStore/SAF 路径不做文件夹定位）。历史与队列内已完成任务一致提供。
- 两端对称、各自记录，不跨端同步；批维度不记历史（per-file 记）。

## Out of scope（本票）

- 逐文件应答、批清单展开（pending 卡不展开文件列表）。
- 移动端历史条目的「文件夹定位」（SAF/MediaStore 无路径语义）。
- 历史单条删除、导出。
