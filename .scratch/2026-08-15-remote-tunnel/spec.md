# 远程隧道（内网穿透）需求规格

> Status: ready-for-human（需求已确认，**暂不实施**，待排期）
> 来源：2026-08-14 grilling 安全评审会话 · 设计盘点见 `design.md` · 架构决策见 `docs/adr/0026-remote-access-trusted-relay-tls.md` · 术语见 `CONTEXT.md`「远程隧道」节

## 1. 背景与目标

BedCode 当前仅适配局域网（两端同一 WiFi）。目标：桌面端通过**插件**实现内网穿透，经用户自购云服务器（中继）让外网移动端连接桌面端，**像在内网一样使用**（终端 WS + 文件服务 HTTP + 插件 HTTP 端点），并在公网暴露前提下完成通信安全加固。

## 2. 使用场景

- **US-1 日常远端**：用户在家里的电脑（桌面端）开着 Claude Code 会话，出门后用手机经中继连回，操作与局域网一致（含文件传输）。
- **US-2 首次接入**：新手机先在局域网完成配对（配对码/QR），之后即可经隧道连接。
- **US-3 暴露控制**：隧道开启期间桌面端状态栏常驻指示，可一键断开；8 小时后自动关闭。

## 3. 范围

### 3.1 做

1. 桌面端隧道插件（中继客户端：注册、心跳、字节转发、暴露控制 UI）
2. 中继服务（自持云服务器：TLS 终止、隧道路由、限速）
3. 移动端远程连接（宿主内置：wss/https 支持、远程发现入口、远程认证流程）
4. 安全加固（JWT 密钥随机化、双层限速、隧道级鉴权、设备准入、暴露控制）

### 3.2 不做（明确排除）

- ❌ 端到端加密（可信中继模型，见 ADR 0026）
- ❌ 自签名证书 / 插件携带 CA 路线
- ❌ 隧道内首次配对（无逃生舱）
- ❌ 移动端隧道插件（移动端宿主内置）
- ❌ P2P 直连（中继转发模式，HostTunnel 抽象保留未来切换可能）

## 4. 功能需求

### 4.1 桌面端隧道插件

- **FR-1** 隧道建立：插件激活后自动向中继出站注册（wss），获得隧道 ID 与公网地址；随服务器启停
- **FR-2** 字节转发：中继公网连接 ↔ 本地 `127.0.0.1:<服务器端口>` 双向透传，**协议无关**（WS + HTTP 全穿），支持多路并发连接
- **FR-3** 心跳与重连：插件↔中继心跳保活，断线自动重连（30s 冷却）
- **FR-4** 暴露控制：状态栏常驻"隧道已开启"指示 + kill switch 一键断开；配置项：暴露时限（默认 8h 自动关闭，可配 1h/8h/24h/常开）、并发设备上限（默认 3）、重连冷却（默认 30s）
- **FR-5** 公网地址展示：桌面端显示公网地址（`wss://relay/t/{id}`）+ 二维码（供移动端扫码）；手动复制兜底
- **FR-6** 异常告警：并发达上限 / 隧道 ID 疑似泄露时桌面端提示

### 4.2 中继服务（云服务器）

- **FR-7** TLS 终止：LE 证书（自有域名），公网入口 wss/https
- **FR-8** 隧道路由：路径 `/t/{id}`，未知 ID 一律 404（不触达桌面端）；桌面端离线时拒绝该 ID 新连接
- **FR-9** 双协议转发：WS upgrade 与普通 HTTP 均按隧道 ID 路由
- **FR-10** per-IP 限速：每公网 IP 20 次握手/分钟（参数可调）

### 4.3 移动端（宿主内置）

- **FR-11** WS 连接支持 wss + 自定义路径（`wss://relay/t/{id}`），TLS 走系统 CA
- **FR-12** HTTP API base URL 支持完整 https URL + 路径前缀（文件服务等全走隧道）
- **FR-13** 发现层"远程"入口：扫码（桌面端二维码）+ 手动输入地址；远程设备进入连接历史/已配对设备（扩展 scheme/path 字段）
- **FR-14** 远程认证流程：仅 JWT 续期 / 生物认证；远程模式下禁用配对码输入并提示"首次配对仅限局域网"

## 5. 安全需求

| 编号 | 需求 | 来源决策 |
|------|------|----------|
| SR-1 | 全链路 TLS：移动端↔中继、中继↔桌面端插件均加密；中继处解密（可信模型） | Q2 / ADR 0026 |
| SR-2 | JWT_SECRET 每安装随机生成 + 持久化（废除硬编码） | Q4 |
| SR-3 | 双层限速：中继 per-IP（20/分钟）+ 应用层每连接 5 次失败/冷却 60s | Q4 |
| SR-4 | 隧道级鉴权：128-bit 高熵隧道 ID 即凭据，中继路径校验 | Q5 |
| SR-5 | 设备准入：首次配对仅限局域网（按 peer_addr 环回判定），隧道只放行已配对设备 | Q6 |
| SR-6 | 新权限 `network:tunnel`：授权文案明确"将设备暴露到公网" | 会话 |
| SR-7 | 暴露兜底：kill switch + 8h 自动关闭 + 并发上限告警 | Q7 |

## 6. 非功能需求

- **NFR-1** 透明性：隧道对上层协议完全透明，桌面端服务器与现有插件零感知
- **NFR-2** 兼容性：隧道与局域网连接可并存（WsSessionRegistry 多客户端）
- **NFR-3** 性能：中继为自持单机，公网 RTT 增加属预期；字节转发开销最小化
- **NFR-4** 配置性：暴露时限/并发上限/冷却参数可配置（插件 storage），默认值经压测校准

## 7. 扩展点需求（待实现时的改动面）

| 端 | 扩展点 |
|----|--------|
| 桌面端宿主 | `HostTunnel` 能力（tunnel_open/send/data/status/close、多路复用、心跳重连）；`get_server_port()`；`server:started/stopped` 事件；`network:tunnel` 权限；认证服务策略（环回禁配对、每连接限次）；JWT secret 随机化 |
| 移动端宿主 | tokio-tungstenite 启用 rustls 后端 + wss/路径支持；useHttpApi 支持 https + 路径前缀；发现层远程入口（扫码/手动）；远程模式配对码禁用 |
| 中继 | 独立服务：TLS、`/t/{id}` 路由、WS+HTTP 转发、per-IP 限速、隧道注册表（形态待定：自写 vs frps 改造） |

## 8. 验收标准（实施时启用）

- [ ] 外网手机经中继连接桌面端，终端会话、文件传输、插件 HTTP 端点均可用
- [ ] 局域网与隧道连接并存互不干扰
- [ ] 未知隧道 ID 连接在中继处 404；新设备经隧道无法首次配对
- [ ] 配对码连续 5 次失败连接被断开；单 IP 超 20 次/分钟被中继拒绝
- [ ] 8h 自动断隧道；kill switch 即时生效；并发第 4 台被拒并告警
- [ ] 重启后移动端 JWT 需重新认证（secret 随机化生效），配对记录保留

## 9. 开放项（实施前需定）

1. 中继软件形态：自写 vs frps 变体（frp 无 per-IP 限速、按端口不按路径）
2. 隧道 ID 编码（32 hex vs base62 缩短）
3. QR 内容格式（仅地址+ID vs 合并配对码）
4. 移动端扫码能力来源（宿主内置扫描 vs 现有 QR 机制扩展）
5. 限速/冷却参数真机压测校准
