# 执行中任务缺少取消入口（队列状态机开环）

Type: task
Status: needs-triage

## 背景

对 auto-task 插件任务队列状态机（`bedcode-desktop/plugins/auto-task/rust/src/queue.rs`）的闭环审查中发现：**waiting / executing 态的队列项没有用户主动取消的路径**。

## 现状

队列操作端点（`handle_queue_http`）只有：

| 操作 | 端点 | 覆盖状态 |
|------|------|---------|
| 添加 | `task-queue/add` | — |
| 删除 | `task-queue/remove` | 仅 `pending`（`remove_task` 直接 DELETE 行） |
| 清空 | `task-queue/clear` | 仅 `status = 'pending'` |
| 编辑 | `task-queue/update` | 仅 `pending` |
| 重排 | `task-queue/reorder` | 仅 `pending` |

`remove_task` 的 WHERE 条件只匹配任意状态行（没有 `status = 'pending'` 限制），但移动端 UI（`AutoTaskPanelHost.vue` 的 `handleRemove`）只对 pending 列表项提供删除按钮；`list_queue` 也只返回 pending。**waiting / executing 项从 UI 上不可见、不可操作**。

`waiting` 项的唯一出口是：clear 送达 → idle 下发、超时重试 ×3 → cancelled、clear 发送失败 → 回退 pending、会话结束 → interrupted。
`executing` 项的唯一出口是：任务终态推送 → done、会话结束 → interrupted。

## 影响

- 用户误将大任务/长任务加入队列后，无法在中途取消（只能等它跑完，或结束整个会话走 Stopped 兜底——副作用是会话内其它任务也被中断）
- 与 `preset-task-execution-state` 规格联动：移动端预设任务入队后处于 executing 时同样无取消手段，用户只能等终态或断会话
- 移动端预设状态机的 `queueItemRemoved`（回退 unused）只覆盖 pending 项被删除的场景，executing 项无对应回退路径

## 建议方案（供实现者评估）

1. **服务端**：`task_queue` 增加取消操作（如 `POST task-queue/cancel`，body: task_id）：
   - `waiting` → 置 `cancelled`（或直接删除）并广播 `cancel`（带 task_id），复用 `check_waiting_timeouts` 的取消广播路径
   - `executing` → 置 `cancelled` + 将对应任务行（task_history 最新行）标 `interrupted`（原因如 "Cancelled by user"）+ 广播 done/cancel（带 task_id，供移动端预设匹配）+ 调 `try_dispatch_next` 继续调度下一项
2. **UI**：移动端面板对 waiting/executing 活动项提供「取消」按钮；桌面端 modal 同理
3. **移动端预设状态**：收到 cancel 广播（带 task_id）时把对应预设置 `interrupted`（与服务端 completed 广播匹配逻辑对齐）
