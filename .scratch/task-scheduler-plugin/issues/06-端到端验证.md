# 端到端验证：CLI 全命令集 + 调度场景 + 互调 + 卸载清理

Type: task
Status: resolved

> 规格依据：`.scratch/task-scheduler-plugin/spec.md` 全部。依赖 01–05 全部完成。

## 任务

1. **CLI 全命令集冒烟**（真实桌面端运行）：
   - `add`（script + inline 双形式）→ `list` → `show` → `run`（手动触发）→ `logs` → `edit` → `enable/disable` → `remove`
   - `--json` 输出可解析；非法参数报错清晰
2. **调度场景**：
   - 秒级 cron（`*/5 * * * * *`）到点触发；`once` 任务触发后自动停用
   - 并发撞车：同一秒 5 个任务 → 3 running + 2 waiting 排队推进
   - 超时：`--timeout 1` 的挂死脚本 → kill + timeout 状态；输出文件保留
   - 错过：桌面端完全退出期间任务到期 → 重启后 missed 执行记录 + next_at 推进
   - DST 缺失时刻（如本地时区 DST 跳变日的 2:30）不触发、不报错
3. **互调**：测试插件通过 ApiClient 调 `schedule.list` 成功；未声明 api 被宿主拒绝（日志断言）
4. **卸载清理**：停用插件 → bedtask 从 PATH 移除、文件删除、原 PATH 其他项保留；重新激活 → 幂等恢复
5. **审计**：执行记录含命令/参数/cwd/env/时间/结果；output 文件可追溯

**期间修复的 3 个 bug（issue 06 捕获，均已在宿主/插件源码修正）**：

1. **激活死锁**（`host.rs activate_plugin`）：WASM activate 期间持 `plugins` 写锁 → scheduler 的 `cli_install` → `services.install_cli` → `plugins.read()` 与写锁互斥死锁（首次激活卡死，CDP 超时暴露）。重构为三阶段短锁（准备字段 → 释放锁执行 WASM → 短锁更新状态），与 mobile manager.rs / deactivate_plugin 模式对齐
2. **启动期 panic**（`host_impl/events.rs broadcast_sync`）：auto-activate 的插件在 `AppContext::init` 前广播 `broadcast_sync` → `AppContext::global()` panic（exit 101）。改用 `try_global()` 静默跳过
3. **catch-up 补跑**（`engine.rs advance_next_at`）：停机后过期任务被 tick 拾起 → `next_after(旧 next_at)` 仍回过去 → 逐秒补跑错过周期。from 改为 `max(旧 next_at, db now)`，错过时间点直接跳到未来周期
