# 调度引擎：cron 解析器 + 数据模型 + tick 状态机

Type: task
Status: ready-for-agent

> 规格依据：`.scratch/task-scheduler-plugin/spec.md` §5（调度引擎）、§6（数据模型）、§7.3（并发/超时）。依赖 01 号 issue（host-process + now_local）。

## 任务

1. **cron 6 段解析器**（自写，零依赖纯函数，`rust/src/cron.rs`）：
   - 语法：`秒 分 时 日 月 周`，支持 `*`、数字、`-`、`,`、`/`、`?`（与 `*` 同义）
   - `parse(schedule) -> Result<CronSpec>`、`next_after(spec, now_local) -> Option<String>`（本地时间字符串 `YYYY-MM-DD HH:MM:SS`，字典序可比）
   - DST：不存在的时刻（如 2:30）跳过该次触发
   - 单测覆盖：边界（每月 31 日、2/29、跨年、闰秒语义忽略）、`/` 步进、多值、秒级触发
2. **数据模型与建表**：`scheduled_jobs` + `job_executions`（按 spec §6 的 DDL）；插件 DB 初始化（lib.rs on_startup 模式）
3. **tick 调度**（宿主 1s timer，命令 `task-scheduler.tick`）：
   - 查询 `next_at <= now_local AND enabled=1` → 插入执行记录（waiting）→ 槽位空出置 running → `host-process` run
   - 完成后：写 exit_code/status/output_path → 计算并写回 `next_at`；`once` 任务成功触发后自动 `enabled=0`
   - 并发上限默认 3（可配，storage 设置），超出排队（waiting）
4. **错过恢复**（on_activate 时，幂等）：
   - `next_at` 已过且超过宽限 120s → 插入 missed 执行记录，`next_at` 推进到下一未来时刻
   - 残留 waiting 行（重启丢失）→ 置 missed
5. **HTTP 端点**：`task-scheduler/` 前缀 `add / list / remove / show / edit / enable / disable / run / logs`（参数校验、http_response 错误码，参照 auto-task queue.rs 模式）
6. **事件广播**：任务/执行记录变更三通道（broadcast_sync + bus + emit_event，参照 scheduled.rs `broadcast_scheduled_changed`）

## 验收标准

- [ ] cron 解析器单测全绿（含 DST 缺失时刻跳过）
- [ ] tick 冒烟：到期触发 → running → succeeded/failed/timeout；`once` 触发后自动停用
- [ ] 错过恢复：构造 next_at 已过 120s+ 的行，activate 后标 missed 且 next_at 推进；waiting 残留置 missed
- [ ] 并发 3 排队：同时到期 5 个任务，3 个 running + 2 个 waiting，完成后依次推进
- [ ] HTTP 端点与 CLI 命令一一对应（此 issue 完成时先用 curl 验证）
- [ ] `cargo test` 全绿
