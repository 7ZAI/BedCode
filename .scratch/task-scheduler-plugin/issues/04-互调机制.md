# 互调机制：manifest api 声明 + 宿主注册表门禁 + JSON-RPC 2.0 + SDK 宏

Type: task
Status: ready-for-agent

> 规格依据：`.scratch/task-scheduler-plugin/spec.md` §9 与 `docs/adr/0017-plugin-inter-plugin-call-gate.md`。此 issue 独立于 01/02/03（无依赖），可并行开工。

## 任务

1. **manifest 声明**：plugin.json 支持 `api` 字段（`["com.bedcode.scheduler.add", ...]` 全限定名数组）；manifest 解析与校验（ADR-0005 单一事实来源链路）
2. **宿主注册表**：插件激活/停用时登记/注销 api 清单（宿主侧 `PluginRegistry` 或复用现有插件状态结构）
3. **总线门禁**：`bus_publish`（host_impl/bus.rs）校验——topic 前缀 `bedcode.api.` 的消息，目标 api 名必须命中某已激活插件的声明清单，否则拒绝 + 告警日志；普通广播 topic 不校验（向后兼容）
4. **JSON-RPC 2.0 消息约定**（SDK 层实现，非宿主）：
   - 请求 topic：`bedcode.api.<plugin-id>.<method>`；payload `{ jsonrpc: "2.0", id, method, params }`
   - 响应 topic：`bedcode.api.reply.<caller-plugin-id>.<request-id>`；payload `{ jsonrpc: "2.0", id, result | error }`
   - 调用方订阅自身响应 topic；SDK 管理 correlation id 配对、超时（默认 10s）、错误传播
5. **SDK `#[plugin_api]` 宏**（`plugin-sdk-desktop` rust 侧）：
   - 实现方：`impl ScheduleApi for MyPlugin` 宏生成 JSON-RPC 分派（解析请求 → 调方法 → 回响应）
   - 调用方：`ApiClient::<ScheduleApi>::new("com.bedcode.scheduler")` 宏生成类型化调用
   - **构建期防漂移**：宏生成的 api 清单与 manifest `api` 字段比对，不一致构建失败
6. **测试插件验证**：`plugin-sdk-test` 扩展或新建测试插件——调用方调计划任务插件声明的 `schedule.list` 拿到结果；未声明 api 的调用被宿主拒绝；调用超时路径

## 验收标准

- [ ] manifest 带 `api` 字段的插件加载时登记；停用后注销（未激活插件目标调用被拒）
- [ ] `bus_publish` 对 `bedcode.api.*` 未声明目标拒绝 + 告警日志；普通 topic 不受影响
- [ ] SDK 测试插件：请求/响应配对成功、错误传播（目标方法返回 error）、超时（模拟无响应目标）
- [ ] 构建期防漂移：改 manifest 不改 trait → 构建失败
- [ ] `cargo test` 全绿
