# 05: 密钥轮换原语（D4）

**What to build:** 给入场签发密钥加轮换能力。**本票的必要性来自票 02 的副作用**：密钥从「从不进 guest」变成「明文躺在 guest 线性内存」，而 `utils/auth/` 下今天**没有任何轮换机制**（已 grep 确认无 rotate/rotation）。

**Blocked by:** 02

**Status:** needs-triage   ← 待用户裁定 Q2

## 为什么必须同批

不做轮换的后果链：guest 侧一次泄露 → 可伪造任意设备凭证 → 7 天 token 窗口
（`DEFAULT_TOKEN_EXPIRY_SECS = 7 * 24 * 60 * 60`）→ **既不能吊销也不能换钥** →
只能全量重新配对。这把 ADR 0031 原本「理论上的」插件密钥风险，换成了
**不可恢复风险**。

**若 Q2 被否**：必须在 ADR 0033 里显式登记「入场密钥泄露 = 全量重配」为
**已接受风险**，不得沉默（AGENTS §0：红线不可被普通任务越过；降级必须留痕）。

## 建议形态（最小可用）

- [ ] 中心持有 `key_id`（当前激活密钥标识），嵌进 JWT claims（`kid`）
- [ ] 保留**上一代**密钥用于验签，宽限期 = 最长 token TTL = 7 天
- [ ] 验签顺序：先试 `kid` 指向的密钥 → miss 则试上一代 → 都 miss 拒绝
- [ ] 轮换触发：宿主命令面手动触发；撤销设备时可级联
- [ ] 轮换本身不撤销既有 token（那是撤销域的职责），只换签发密钥
- [ ] 超出宽限期的旧密钥从存储删除（有界保留，不无限累积）

## 关键实现事实

- claims 加 `kid` 是 **wire 格式变更**（向后兼容：旧 token 无 `kid` 字段，
  按「验上一代」路径处理）
- 移动端把 token 当**不透明串**，不解析 claims → **移动端零改动**
- 密钥存储仍在 `plugin_secrets`（属主 = 中心），轮换即在同一 key 名下换值或加
  `jwt.key.<gen>` 形式的多代条目
- **凭据红线**：密钥材料禁止进日志、禁止进错误文本、禁止进文档（AGENTS §8）。
  日志只记 `key_id` 与长度

## 验收

- 轮换后：新签发 token 用新 key 验签通过；宽限期内旧 token 仍验签通过
- 超出宽限期：旧 token 验签拒绝
- 轮换幂等：重复触发不产生多余代次
- 变异自检：把「验上一代」分支删掉，跨代用例必须转红
- 日志检查：`grep` 轮换路径的日志输出，确认无密钥明文
