# 移动端受损清单（传输编排下沉票 4）

> **裁决（spec 开放点 5，2026-09-25）**：移动端不变，先做好桌面端再说——允许损坏 + 受损清单
> 如实记账（session-engine-downsink 先例）。移动端 SDK ABI = 11 不跟演；本清单逐条列出
> 「移动 file-transfer 插件（按 mobile SDK 11 构建）接入桌面 v31 宿主」时的行为差异。
>
> **前置事实**：host-peer 是 desktop 独有接口（mobile WIT 无此 interface，ADR 0022 双端偏离），
> 移动端文件传输的对等网络面在移动宿主侧另有原生实现（移动 `plugins/file-transfer/` 走
> 移动宿主的 peer 通道），与桌面 host-peer 原语不共 ABI。下表差异均在「跨端直连」场景
> （移动端作为对端与桌面 v31 宿主传输）成立。

## 1. 不受影响（桌面侧自洽闭环）

| 面 | 说明 |
| --- | --- |
| 数据面协议（wire） | TLS 1.3 直连 + 自定义线协议（offer/progress/pause/resume/cancel 帧）零改动——`packages/peer-net` crate 双端共享 |
| 发现与信任 | mDNS `_bedcode-peer._tcp` 广播、首连确认、信任存储双端语义不变 |
| 断点续传 | 落盘断点真源在接收端磁盘，v31 收窄不触数据面 |
| 桌面 file-transfer 插件 | 已按 v31 SDK 重建，事件归约状态机自持全部任务真源 |

## 2. 受损/行为差异（移动端视角）

| # | 差异 | 根因 | 表现 | 影响 |
| --- | --- | --- | --- | --- |
| 1 | 桌面端接收策略并发脉冲 | 桌面 `send-files` 载荷 `concurrency` 字段 v31 退役（出现即报错） | 无——该字段由**桌面插件**发出，移动端从不发它 | 无实际影响（移动端不是 host-peer 调用方） |
| 2 | 桌面端发送并发行为 | 桌面并发闸门下沉插件 | 移动端作为**接收方**无感知；桌面侧并发节奏由桌面插件自控 | 无 |
| 3 | 移动端**作为发送方**向桌面发文件 | 桌面接收闸门（ask/always_*）经 `set-receive-policy` 推送，策略面不变 | 行为不变 | 无 |
| 4 | 移动端作为拉取方浏览/拉取桌面共享根 | 桌面 `pull-files` 收窄「逐文件即发」 | 桌面侧 `pull-started` 事件只进桌面插件总线（`peer:receive-event`），移动端拉取路径走**移动宿主原生实现**，不经桌面 WIT | 无 |
| 5 | **移动端收到「恢复全部」语义变化** | 桌面 `resume-all-transfers` WIT 退役 | 移动端从不调用桌面 host-peer → 无影响 | 无 |
| 6 | 快照事件（peer:transfer / peer:receive）退役 | 桌面端 topic 形态变化（ACL 语义） | 移动端总线与桌面总线**物理隔离**（各自宿主进程内总线），不跨进程 | 无 |
| 7 | 桌面 serve 供流记账视图 | 桌面端 send 记账行改由桌面插件自建 | 移动端发送文件给桌面后，桌面 UI 的发送记账行**首屏可能短暂缺 peer_name**（桌面插件从自持设备缓存解析，缓存未命中时以短指纹兜底） | 低——展示名兜底短指纹，progress 事件到达后行内字段补全 |

## 3. 结论

**当前无实际跨端受损**：host-peer 原语是 desktop 独有面，移动端不作为其调用方；wire 数据面
协议零改动；两端总线物理隔离。唯一可观测差异（#7）仅是桌面端 UI 的展示名兜底路径变化。

**未来若移动端要复用 v31 语义**（例如移动 SDK 升级引入 host-peer）：必须按 v31 契约重建——
不 import `resume-all-transfers`、不发 `concurrency` 载荷字段、消费 `peer:*-event` 事件流。
任何一步缺失都会 fail-visible（实例化期 / 调用期显性报错），不会静默降级。
