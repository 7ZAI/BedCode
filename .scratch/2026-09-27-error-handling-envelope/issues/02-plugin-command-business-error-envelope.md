# 02：插件命令与业务错误信封（宿主桥 marker 透传 + SDK 辅助 + 插件域前端接入）

**Type:** task
**Spec:** `../spec.md`（§2 插件契约 / §4 P2 + P3 插件域子集 / §3 B 组局部、A 组插件键）；契约单一事实源 `docs/adr/0030-error-envelope-and-user-prompt-boundary.md`（决定 6）
**Blocked by:** 01
**Status:** done（2026-09-27；票 03 由并发 agent 并行推进，04/05 待做）

**What to build:** 用户执行插件相关操作（启用/停用、安装、卸载、批准、插件详情命令）失败时，界面只显示友好提示；插件按其业务语义定义自己的错误码——业务失败（如「会话不存在」）显示插件自己 i18n 里的文案，宿主机制失败（如「应用未启用」「应用不存在或已卸载」）显示宿主通用文案。用户始终看不到错误原文，插件作者也无需为「如何不泄漏技术细节」操心——SDK 提供带码返回的辅助工具，宿主只做形状检测与透传、不解释业务语义（零 ABI 变更，插件不必重建）。

**集成测试约束（用户指令）**：本票**只编写**集成测试文件，**不执行**；统一在票 05 全量执行。

**Acceptance:**

- [ ] SDK 辅助：插件可「带业务码 + 具名参数」返回错误（标记信封形态）；WASM 导出签名不变（不 bump ABI、不重建既有产物）
- [ ] 宿主桥：只做机制检测（标记）与形状校验——是 → 透传给前端（不解释业务语义）；否/畸形 → 按兜底码 + 插件标识参数处理、原文进日志
- [ ] 宿主机制码落地：`host.plugin.not-activated` / `not-found` 等显式友好码（对应 i18n zh + en）
- [ ] 插件模板预置 `errors.*` 文案骨架；选定一个第一方插件（或模板）落地首批业务码示例
- [ ] 插件域前端接入：启用/停用/安装/卸载/批准/插件详情共约 6 处错误展示全部走统一消费层（友好文案 + 日志）；对应 i18n 键去 `{error}` 插值
- [ ] 单元测试全绿（针对性过滤，不跑集成）；**编写**（不执行）覆盖「带码业务错误 → 友好文案、畸形/未标记 → 兜底」的集成测试
- [ ] 交付说明：grep 复核本票范围内无技术原文直显
