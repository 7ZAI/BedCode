## 实施记录（2026-09-19）

**桥接架构（`src-tauri/src/utils/auth/auth_center.rs` 新模块）**：双轨并存期桥接层——
认证中心（`com.bedcode.devices`）激活时配对码/QR token 生命周期操作经互调 api
（ADR 0017、JSON-RPC 2.0 over host-bus）转发认证中心实现（状态以认证中心为准）；
未激活或互调失败降级宿主实现（迁移前行为，无单点）。消费方 = Tauri 命令面
+ server 配对端点（**移动端验签与前端展示必须同源**，否则生成/验证落在不同状态存储上破坏配对流程）。

- **认证中心互调 api 面新增 8 个**（manifest api 3→11；`#[plugin_api]` 防漂移两侧同步）：
  `pairing-code-generate/status/verify/clear` + `qr-code-generate/status/verify/clear`；
  与命令面（`devices.pairing.*`）共享同一状态源（lib.rs 提取共享函数）+ 4 个 native 单测；
  返回形状对齐宿主 DTO（PairingCode serde：code/created_at/expires_in 剩余；QR：token/ttl/remaining）
- **file-transfer `AuthCenterApi` 镜像 trait 补齐 8 stub**（构建期防漂移要求 trait 方法集 = manifest.api 精确一致；本插件不消费）
- **桥接 ops**：generate/current/verify/clear × 配对码与 QR；`qr_conn_info` 只回
  (token, remaining)，host/port 组装（局域网 IP/端口配置）留命令层（宿主引擎配置域）；
  `QrVerifyOutcome::Rejected(reason)` 携带与宿主 `QrTokenManager` 错误文本同构的分类原因，
  失败提示分类抽 `qr_failure_user_message` 单点维护（原 auth_controller 内联 contains 逻辑迁移）
- **TTL get/set（pairing_code_ttl / qr_token_ttl）留宿主 DB 设置**（配置域；生成命令把配置值传入插件 generate）
- **历史 / 已配对设备（DB pairings）/ 在线设备列表（WS 注册表）留宿主内核存储**：
  spec §3「不动」表；插件 trust 为独立镜像库（host-storage `trust.pairings`），转发会造成
  数据分叉回归（存量配对不可见）——归票 13 退役时随数据源整合一并处理
- **宿主调用机制**：`WasmHostContext::call_plugin_api_host` 新方法（委托 host_impl api_call，
  调用方身份常量 `HOST_API_CALLER_ID="bedcode-host"`，reply topic 路由用；互调门禁只校验
  目标 api 声明、不校验调用方）；JSON-RPC wire 宿主侧本地实现（SDK api_call 模块被 wasm
  feature 门禁）；**request id 全局 AtomicU64**（宿主多线程并发调用，reply topic 含 id，
  必须全局唯一防串台——SDK thread_local 只适用 wasm 单线程）
- **接线**：commands/system.rs 配对码 4 命令、commands/qr.rs QR 3 命令、auth_controller
  request_pairing / verify_pairing_code / qr_connect 3 端点全部改经桥接层；
  命令签名新增 `host: State<PluginHost>`（Tauri 注入，前端零改动）
- **宿主闭环 `test_host_pairing_bridge_closed_loop`**：真实 devices 产物 → 激活路径
  配对码/QR 全生命周期经互调（一次性、消耗后状态、QR reason 分类）；注销注册表
  （模拟停用）→ 降级宿主 PairingService/QrTokenManager（迁移前行为）
- **教训**：① 插件宏分派 `match req.method` 按**短方法名**匹配（topic 全限定
  `bedcode.api.<plugin>.<method>`、payload `method` 字段短名）——桥接首版 payload 传全限定名，
  插件静默不回复（`_ =>` 分支）导致 5s 超时降级，全部断言被降级路径「静默通过」掩盖
  （QR reason 带 `Authentication error:` 前缀才暴露）；加 wire 捕获诊断定位（请求到达 topic
  静态订阅但插件无回复）② 测试断言要能区分插件路径与降级路径（仅报错误前缀差异）
