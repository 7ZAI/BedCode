# 远程隧道插件——设计盘点（安全评审会话产出）

> 需求规格见同目录 `spec.md`（已确认，暂不实施）
> 会话日期：2026-08-14 · 方式：grilling + domain-modeling
> 关联：ADR `docs/adr/0026-remote-access-trusted-relay-tls.md`、`CONTEXT.md`「远程隧道」节

## 1. 目标

桌面端以**插件**形式实现内网穿透：经自购云服务器（中继）让外网移动端连接桌面端，像在内网一样使用（终端 WS + 文件服务 HTTP + 插件 HTTP 端点），并在公网暴露前提下做通信安全加固。

## 2. 架构（最终形态）

```
移动端（宿主内置连接）                   中继（自购云服务器，可信）                   桌面端
┌──────────────────┐   wss/https    ┌────────────────────┐   wss（出站）   ┌──────────────────┐
│ ws_connect wss   │───────────────▶│ TLS 终止（LE 证书） │───────────────▶│ 隧道插件          │
│ https HTTP API   │                │ 路径路由 /t/{id}    │   隧道注册/心跳   │ HostTunnel        │
│ 扫码/手动输入地址  │                │ WS+HTTP 双协议转发   │                │   └─▶ 127.0.0.1   │
└──────────────────┘                │ per-IP 限速         │                │      :8765（明文环回）│
                                    └────────────────────┘                └──────────────────┘
```

- 业务流量在中继处解密后明文转发（可信中继模型，不做 E2E）
- 每条公网连接 → 独立本机连接（frp 式），桌面端服务器按 `127.0.0.1:port` 识别隧道连接

## 3. 决策摘要

| # | 决策 | 结论 |
|---|------|------|
| Q1 | 中继信任模型 | **可信中继（自购云服务器）**，不做端到端加密 → ADR 0026 |
| Q2 | 传输层 TLS | **域名 + Let's Encrypt 全链路 TLS**（两端公网段 wss/https，中继终止）；放弃自签名+插件带 CA（需 3 个移动端 TLS 注入扩展点且无私钥吊销机制） |
| Q3 | E2E 密钥方案 | 不做（随 Q1 下桌） |
| Q4 | 凭证加固 | **双层限速**：中继 per-IP 20 次/分钟 + 应用层每连接 5 次失败/冷却 60s；**JWT_SECRET 硬编码 → 每安装随机生成 + 持久化**（前置条件，已签发 JWT 作废） |
| Q5 | 隧道级鉴权 | **128-bit 高熵隧道 ID 即凭据**（`wss://relay/t/{id}`，中继路径校验）；移动端 **QR 扫码为主 + 手动输入兜底**；认证仍走配对码/生物 |
| Q6 | 设备准入 | **首次配对仅限局域网**（按 peer_addr 是否环回判定）；隧道只放行已配对设备（JWT 续期/生物认证），无逃生舱 |
| Q7 | 暴露控制 | **kill switch（必做）** + 8h 自动关闭 / 3 台并发上限 / 30s 重连冷却（默认值，可配置） |
| Q8 | 移动端归属 | **宿主内置**（核心通道形态扩展归宿主，独立功能归插件） |

## 4. 扩展点清单（需预留/实现）

### 4.1 桌面端插件宿主（Rust）

| 扩展点 | 说明 |
|--------|------|
| `HostTunnel` 宿主能力 | 双向字节通道：`tunnel_open(relay, id)` / `send` / 事件 `tunnel_data` / `tunnel_status` / `tunnel_close`；**协议无关透明管道**（WS+HTTP 全穿）；多路复用（并发连接）+ 心跳重连；TLS 出站走系统 CA |
| 服务器信息 API | `get_server_port()`（插件需知本地端口建环回连接） |
| 服务器生命周期事件 | `server:started` / `server:stopped`（隧道随服务器启停） |
| 权限 `network:tunnel` | 走 PermissionManager + manifest 声明，授权文案明确"将设备暴露到公网" |
| 暴露控制 UI | status bar 常驻"隧道已开启"+ kill switch；配置项（时限/上限/冷却）存插件 storage |
| 认证服务策略（宿主） | peer_addr==环回 → 禁止首次配对；每连接配对尝试 5 次失败/冷却 60s |
| JWT secret 随机化 | 每安装随机 + 持久化（独立前置项） |

### 4.2 中继（云服务器）规格

- TLS 终止（LE 证书，正式域名）
- 路径路由：`/t/{id}`，未知 ID 一律 404（不触达桌面端）
- WS upgrade 与普通 HTTP 双协议转发（文件服务走 https）
- per-IP 限速（20 次握手/分钟）
- 隧道注册/心跳/会话表：桌面端出站注册获 ID，离线即拒绝该 ID

### 4.3 移动端宿主

| 扩展点 | 现状 → 需要 |
|--------|-------------|
| WS 连接 URL | `ws_connection.rs` 只拼 `ws://`，且 `tokio-tungstenite` **未启用任何 TLS 后端 feature** → 加 rustls 后端 + 支持 wss/自定义路径 |
| HTTP base URL | `useHttpApi.setApiBaseUrl` 支持完整 https URL + 路径前缀（reqwest 已有 rustls-tls，系统 CA 信任 LE，零配置） |
| 发现层 | DiscoverView 加"远程"入口：扫码 + 手动输入；RemoteDevice / connectionHistory 字段扩展（scheme/path/type） |
| 认证流程 | 远程模式禁用配对码输入（提示"首次配对仅限局域网"），走 JWT 续期/生物认证 |

## 5. 分层防御（纵深）

```
公网扫描者 ──▶ ① 中继 TLS+per-IP 限速（摸不到隧道）
隧道 ID 泄露 ─▶ ② 中继路径校验（/t/{id}，未知 404）
拿到 ID ────▶ ③ 首次配对仅限局域网（新设备进不来）
已配对设备 ──▶ ④ 每连接 5 次失败/冷却（暴力无效）
合法设备 ────▶ ⑤ JWT（随机 secret）+ 生物认证（防重放 nonce）
并发异常 ────▶ ⑥ 3 台上限 + 告警、8h 自动关闭、kill switch
```

## 6. 开放项

- 中继软件形态：自写 vs frps 变体（frp 无 per-IP 限速、按端口不按路径，需确认改造量）
- 隧道 ID 编码：32 hex vs base62 缩短（影响二维码密度）
- QR 内容格式：仅地址+ID（认证另走配对码）vs 将来合并配对码
- 限速/冷却参数真机压测后校准
- 移动端扫码能力：宿主内置二维码扫描（现无），或复用现有 QR 机制扩展
