# 桌面端 DB 与 HTTP 基础服务化完备性补齐

Status: `done`
Date: 2026-09-18
范围: **仅桌面端**（`bedcode-desktop/`）；移动端不动（ADR 0018 契约独立，host-http / host-database 语义两端对齐，见 §Out of Scope）
来源: db/http 基础服务化审计（2026-09-18，全证据在 scratchpad [01a0b4b6] 与下方 Implementation Decisions）

## Problem Statement

桌面端已按「基础能力服务」模式为插件提供 DB 与 HTTP 能力：WIT 原语（`host-database` / `host-plugin-database` / `host-http`）+ 宿主实现 + 真实消费插件（auto-task、agent-hub、ai-chatbox、file-transfer 已实际调用）。但审计发现这些服务「原语齐、护栏缺」，存在三类问题：

1. **插件可无防护地劣化乃至破坏内核**：主库是内核与全部插件共用的单一连接（全局 `Mutex<Database>`）。DB 域无 SQL 执行超时、无结果集上限——一条慢查询会阻塞整个内核 DB（配对、会话配置、设置读写全部排队）；无事务原语，插件用裸 BEGIN/COMMIT 拼多调用时，事务窗口内内核自己的写入会插进插件事务，插件 ROLLBACK 会一并丢弃内核写入。
2. **HTTP 权限断链**：`host-http` 宿主实现**不做任何权限仲裁**（全仓库唯一零 `check_permission` 的 IO 域），`network:http` 权限仅在前端能力映射生效；WASM 插件即使 manifest 不声明该权限也能经 host 原语发起任意 HTTP 请求——违反「manifest 声明权限 + Rust 端最终仲裁」的既有契约。
3. **宿主携带业务语义 + 端点无治理**：宿主硬编码 OpenAI SSE 解析（`streamEvent` + `choices[].delta.content`）——ai-chatbox 的产品语义长在内核里，违反「无业务内核」红线；服务端 `/api/plugin/{id}/...` 静态 ANY 路由，端点声明注册表是死代码（无 404 治理、无属主回收、无路径冲突保护），请求不透传 headers、响应强制 JSON，无 JWT 门禁的信任模型未文档化。

## Solution

按「基础能力服务」完备标准补齐两域护栏，保持**零业务语义下沉、行为向后兼容**：

- **DB 域**：为主库与插件独立库的执行面加三类护栏——SQL 执行超时（progress handler 硬中断）、查询结果行数/字节上限（超限截断并报错，护栏由宿主固定、插件不可调）；新增事务原语 `execute-batch`（单次调用内原子执行多语句，宿主全程持有连接），并文档化「禁止跨调用裸 BEGIN/COMMIT」。
- **HTTP 客户端域**：补 `network:http` 权限仲裁（对齐其他域既有 `check_permission` 模式，无新机制）；移除宿主内 OpenAI SSE 格式解析，宿主只透传原始 chunk / 通用 SSE 事件帧，格式解析下沉插件。
- **HTTP 服务端域**：把既有的端点注册表接线为真实治理面（activate/manifest 声明 → 注册；路由先查注册表，未注册 404），保持旧前缀 ANY 兼容；请求透传 headers（白名单）；端点无 JWT 门禁的信任模型以文档固化（不改门禁行为）。
- **文档化**：DB 二进制（BLOB→hex）与 i64 精度限制写入 SDK 注释/SDK 文档，不给本期新增 ABI 面。

## User Stories

1. 作为插件作者，我想要插件执行 SQL 有超时与结果上限护栏，以便我的慢查询或 bug 不会阻塞其他插件与宿主内核的数据库读写。
2. 作为宿主维护者，我想要 DB 护栏由宿主固定、插件不可调，以便安全边界不依赖插件自觉。
3. 作为插件作者，我想要在激活时一次性原子地建表 + 写入种子数据，以便初始化要么全部成功、要么全部回滚，不会留下半初始化状态。
4. 作为宿主维护者，我想要插件无法用跨调用裸事务把内核写入卷入回滚，以便恶意或出错的插件不能静默丢弃内核数据。
5. 作为插件作者，我想要 manifest 声明 `network:http` 是发起 HTTP 请求的前提，以便权限模型前后一致、前端与 Rust 端双重仲裁。
6. 作为安全审计者，我想要 WASM 插件未声明 `network:http` 时调用 host-http 得到明确的权限拒绝错误，以便证明 Rust 端仲裁真实生效。
7. 作为插件作者，我想要流式 HTTP 响应的原始 chunk 透传给插件（而非只推前端事件），以便无头调度/代理类插件也能消费流式 API。
8. 作为宿主维护者，我想要内核不再解析任何供应商专属的 SSE 格式，以便内核保持零业务语义、新增格式不需要改内核。
9. 作为 ai-chatbox 插件作者，我想要 OpenAI SSE 解析逻辑回归插件自身，以便宿主升级不再携带我的产品语义。
10. 作为插件作者，我想要会话代理端点的挂载点是可声明的（activate 时声明路径），以便我声明的路径之外返回 404、路径冲突能被宿主拒绝。
11. 作为主机用户，我想要插件端点对局域网暴露的信任模型有明确文档，以便我理解谁可以访问、插件自己该做什么认证。
12. 作为插件作者，我想要端点请求能收到调用方 headers（白名单内），以便需要按 header 鉴权/路由的插件端点可用。
13. 作为插件作者，我想要端点响应能选择 content-type，以便非 JSON 的端点（文本、事件流）可用。
14. 作为插件作者，我想要把二进制数据存入数据库（或明确得知只能 hex 存 TEXT），以便存储限制是文档化的契约而非运行时意外。
15. 作为插件作者，我想要查询返回的大整数不会在 TS 侧丢精度（或明确得知该限制），以便不与标识符/时间戳类型冲突。
16. 作为现有插件维护者（ai-chatbox / auto-task / agent-hub / file-transfer），我想要本轮全部改动对既有调用与 manifest 零迁移，以便升级宿主不破坏已装插件。
17. 作为移动端协作者，我想要桌面端这些护栏改动不触碰移动端契约，以便两端 ABI/语义各自演进（ADR 0018）。
18. 作为测试工程师，我想要每个护栏都有正反例测试（超时触发/不触发、上限截断/放行、权限拒绝/放行），以便行为契约可回归。

## Implementation Decisions

- **DB 执行护栏（统一模式）**：主库与插件独立库共用同一套护栏实现。超时用 SQLite progress handler 在宿主侧硬中断（rusqlite bundled 可用）；结果行数与序列化字节数在取行循环内计数，超限立即截断并返回带明确错误消息的结果。护栏常量进宿主常量域，语义对齐 HTTP 响应体上限（32MB）的既有模式；**护栏不可由插件参数调整**（安全边界）。超时默认值为保守常量（建议对齐 HTTP 总超时语义，最终值实现时定）。触发护栏的调用记 `warn!` 结构化日志（`plugin_id` 字段），并保留「超时/超限」与「SQL 错误」的错误区分，插件可按类处理。
- **DB 事务原语**：新增 `execute-batch`（主库与插件独立库各一）：单次 WIT 调用内宿主持有连接锁、事务内顺序执行多语句，任一句失败全部回滚，返回受影响行数合计。文档化并（如实现简单）校验拒绝「裸 BEGIN/COMMIT 跨调用」模式：`execute`/`execute-params` 若完整 SQL 以事务控制语句开头/结尾（BEGIN/SAVEPOINT/COMMIT/ROLLBACK 白名单），返回明确错误引导使用 `execute-batch`。事务窗口内不再有内核用同连接插队的窗口——这是 D2 完整性的关键。
- **DB 二进制与精度**：本期**不改 WIT / 不新增 ABI 面**。BLOB 读出 hex、参数绑定 JSON 字符串语义保持现状，限制写入 SDK 文档与注释（用户故事 14）。i64 精度同理写成已知限制（建议插件主键用 TEXT/自增整数，不依赖 >2^53 的 JSON number 往返）。
- **HTTP 客户端权限仲裁**：`host-http.fetch` 入口补 `check_permission`（`network:http`），完全复用其他域既有权限检查的签名、语义与测试模式——无新机制、无配置项。这是合规修复（影响 WASM 路径；TS 路径前端已 fast-fail）。**注意**：这是行为收紧，理论上可能暴露「已装插件 manifest 未声明 network:http 却实际在用 host-http」的存量违规——实现时必须全仓核对既有插件 manifest（ai-chatbox / agent-hub 必看），漏声明的一并处修（属权限声明修正，非行为破坏）。
- **HTTP 流式重构（零业务语义）**：从宿主删除 OpenAI SSE 结构与其解析（保留通用 SSE 事件分隔透传能力或回退为纯原始 chunk 事件，二选一在实现时定，倾向「通用 SSE 事件帧：只切分事件、透传 data 行原文」——仍无供应商语义）；`sseFormat` 特殊格式名由插件自管。宿主只做「字节流 → 事件」的引擎级转换与背压；`openai` 解析逻辑迁移回插件层（ai-chatbox 消费方自行按格式解析，或由前端既有解析接管，实现时与消费插件确认消费侧形态）。流式数据目前经前端事件通道投递；插件侧直接消费流是**后续单独票据**（needs-decision，属 host-websocket / 消息总线定向投递的延伸，不在本期强解）。
- **服务端端点注册治理**：接线既有注册表——插件 activate 时按 manifest/导出声明注册端点路径，deactivate/卸载时按属主回收；HTTP 路由先查注册表再转发，未注册 404（旧插件/静态路由行为通过「未声明 = 前缀内放行」兼容策略过渡，需在实现时定兼容细节，默认目标：注册表接线后不破坏现有 auto-task 端点）。路径冲突（两插件同路径）由注册拒绝 + 明确错误实现。
- **服务端端点请求面**：向插件透传白名单内的请求 headers（白名单避免透传全部头带来的枚举面）；响应侧支持插件指定 content-type（默认保持 application/json）。TS-only 插件的端点桥接（前端事件桥）仅记录为已知缺口，本期不动——端点仍为 Rust/WASM 插件能力（现状语义）。
- **信任模型文档化**：`/api/plugin/*` 无 JWT 放行（hook 脚本场景）+ 仅激活检查 + 0.0.0.0 监听的现实，以 ADR 或 knowledge 文档固化（写端点必须插件自查认证）。**不改门禁行为**（移动端/脚本兼容）。
- **不动的内容**：主库 SQL 前缀隔离规则、插件独立库文件模型、URI 前缀 `/api/plugin/{id}/`、WS 基础服务（另票）、WIT ABI 版本（本期除 execute-batch 新增函数外不 bump；execute-batch 属于接口追加，按既有惯例进 ABI 版本次要递增）。

## Testing Decisions

- **测试哲学**：只测外部行为——即插件视角调用 host 接口的成败/返回值/错误分类，不测内部实现（不 mock 连接、不 assert 调用顺序）。每个护栏一张正反例矩阵：超时（慢查询触发 / 快查询放行）、行数/字节上限（超限截断并报错 / 限量内放行）、权限（未声明拒绝 / 声明放行）、事务（任一句失败整体回滚 / 全部成功原子可见）。
- **Seam（优先单一接缝）**：首选既有 **WIT host 接口调用层**（`host_impl` 入口函数签名，已有对应单测模块）；纯逻辑走既有纯函数 seam（SQL 前缀校验、列转换、跳转裁决、端点状态解析均有独立纯函数 + 单测先例）。**不新增模块**；组件级闭环测试复用既有 fixture 插件（WASM fixture 经 host 接口走真实调用链）。
- **先例**：宿主域单测模块（各 `host_impl` 文件内 `mod tests`，含权限门禁正反例）；database 域单测（表前缀校验、列→JSON、参数绑定）；HTTP 域单测（跳转裁决/请求参数解析）；端点注册表单测与 `plugin_controller` 纯函数测试（状态码区间）。权限门禁的测试形态参照 `host_impl/mod.rs` 既有 `check_permission` 测试。
- **回归**：真实消费插件（ai-chatbox / auto-task / agent-hub / file-transfer）相关既有测试全绿；桌面 `cargo test` 全绿；`pnpm exec eslint .` 0 error；完成定义按 AGENTS.md §10。

## Out of Scope

- **移动端**：契约独立（ADR 0018），两端语义保持对齐、桌面侧不触碰移动端代码；host-http / host-database 的护栏差异仅存在于桌面端实现内。
- **WS 基础服务 + host-websocket 原语**：独立票据 `.scratch/2026-09-18-ws-base-service/`，互不阻塞。
- **插件直接消费流式响应**：本期只做「宿主零业务语义」重构；guest 侧流式消费形态留后续设计（消息总线定向投递延伸）。
- **完整 HTTP 客户端扩展**（multipart 上传、流式请求体、per-request 超时、二进制响应体）：记录为已知缺口，不入本期。
- **端点安全升级**（如给 `/api/plugin/*` 加独立 token / 按插件粒度鉴权）：仅文档化现状，不改门禁。
- **TS-only 插件端点桥接**：现状语义（端点 = Rust/WASM 插件能力）保持。
- **DB 能力面扩展**（schema 迁移工具、查询计划器、连接池化）：不做；单连接模型是既有架构决策。
