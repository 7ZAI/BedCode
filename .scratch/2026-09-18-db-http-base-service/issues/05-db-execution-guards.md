# 05 — 主库/插件库执行护栏：SQL 超时 + 结果上限

**What to build:** 修复审计发现 D1（内核可用性风险）。为宿主 DB 域（主库 + 插件独立库，8 个既有入口统一）加两类护栏：

- **SQL 执行超时**：SQLite progress handler 在宿主侧硬中断慢查询（rusqlite bundled 可用），超时触发即返回「查询超时」类错误。默认值实现时定（建议语义对齐 HTTP 总超时，保守起步）。
- **结果集行数 / 序列化字节上限**：取行循环内计数，超限立即截断并返回带明确说明的错误（引导插件加 LIMIT 或分批）。上限常量进宿主常量域，不可由插件调整（安全边界，插件可传 LIMIT 但护栏是兜底）。

错误分类保持可区分：超时/超限 vs SQL 语法/约束错误 vs 权限拒绝，插件按类处理。触发护栏记 `warn!` 结构化日志（`plugin_id` 字段，AGENTS.md §8 格式）。

**关键背景：** 主库是内核与全部插件共用的单一连接（全局 `Mutex<Database>`），慢查询会阻塞配对/会话配置/设置等全部内核 DB 读写——护栏是内核可用性保护，不是插件便利性功能。
