# 12: 文档与路线图收尾（P4 对外记账）

**What to build:** 让「会话是真源在插件的产品概念、宿主只有引擎」这件事在**所有对外入口**
都是一句能查到的话：AGENTS 的红线与检查项、ADR 的边界裁决、code-map 的目录地图、
CHANGELOG 的双语条目、路线图的阶段状态与本 spec 的验收清单同步到完成态。
做完之后，下一个人不需要读这 12 张票就能知道边界在哪、为什么。

**Blocked by:** 11（只有内核目录真删了，文档才能写完成态；提前写会变成又一处「文档与实现不符」）。

**Status:** ready-for-agent

## 验收标准

- [ ] AGENTS：§5 无业务内核的红线把「会话」从「暂留宿主侧」清单里摘除并给结论；
      §7 的会话真源检查项从「P1-b 现状 + P4 待退役」改写为终态（原语清单里不再有会话域、
      `ptyQuota` 与 PTY 三件套的措辞复核）；§8 的「真源换了地方就要 fail-visible」
      保留为通用判据并把本专项写成先例
- [ ] ADR 0022：新增一条修订（v14 或当时最新号）——会话原语域退役完成、
      host-pty 划界从「两张注册表」改成终态表述、双端偏离段的 ABI 计数与版本更新
- [ ] 桌面 code-map：内核会话目录条目消失、宿主能力域一节去掉会话原语、
      会话相关 Quick Navigation 只剩「插件真源 + 窄转发层」两条；顺带清掉本专项期间
      留下的「遗留线/待 P4」标注
- [ ] CHANGELOG：一条完成态条目（改进段），覆盖「宿主零会话对象 + 会话原语退役 +
      形态 B 输出面 + 实测结论」，破坏性变更与「旧产物按新 SDK 重建」在 Security/Platform
      段落点名；版本号规则复核（桌面/移动同步维护的口径是否被本专项触及）
- [ ] 路线图：阶段 3 从 ◐ 改 ✅（会话+终端两条都下沉完），阶段 4 的状态与下一步推进；
      移动端受损清单 M6/M7 若已在 06 恢复则改「已恢复」并保留 P4 之后仍受损的条目
- [ ] 本 spec：§6 验收清单逐条落到最终态（含 ◐ 那条事件面项收口）、
      票末「票据拓扑」节标注哪些票已 done、哪些产物被后续票取代
- [ ] 交叉引用自查：spec 里点名的路径/模块/命令字眼与仓库实况一致（AGENTS §12 的
      code-map 优先纪律、命令字眼必须跟工具链）
- [ ] 文档改动单独成 commit（`docs(...)`），不与代码混提

## 边界与不做

- 不改任何代码行为。
- 不重写历史票内容（只在各自票末记 done 与结论）。
- 不新增架构决策；若收尾时发现需要新决策，另立 ADR 而不是塞进本票。
