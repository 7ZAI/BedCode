# 12: 注解槽 contract——摘除内核任务语义字段

**父规格:** `.scratch/2026-09-19-terminal-session-plugin/spec.md` D5 / D8-P2

**What to build:** 内核的会话记录里不再有任何任务语义：四个产品字段与其枚举定义从会话结构中删除，只剩不透明注解槽。用户与移动端看到的字段值不变（由槽透传），但内核代码读到这些键时不再知道它们是什么意思。

**Blocked by:** 11（双写稳定、所有读者已改从槽取值）

**Status:** done（2026-09-20；引擎记录摘除四字段 + `TaskStatus` 枚举删除；对外形状经新视图 DTO 从注解槽取值，逐字段不变；全量门禁绿）

## 实施记录（2026-09-20）

### 1. 引擎记录去语义（`session/session_event.rs`）

- `SessionInfo` 摘除 `task_status` / `task_reason` / `task_updated_at` / `task_questions` 四字段与相关 import——它只剩进程与输出描述（id / configId / name / status / 时间戳 / sessionType）。
- 新增**对外视图** `SessionInfoView`：`#[serde(flatten)] info` + 四个任务字段（`skip_serializing_if` 同迁移前）→ JSON 形状与 contract 前**逐字段一致**（前端 `list_sessions` / `get_session` 契约不变）。
- 新增 `task_fields_from_slot(annotations)`：**键名 → 对外字段名的唯一机械映射**（迁移期兼容层）。内核据此只做「槽值 → 字段」原样转发，不解释取值含义（spec D5）：
  - 键缺失或**空串** → 字段不出现（等价迁移前 `None`；`annotate` 允许空值，空值不产出「有键无值」形状）
  - `taskQuestions` 槽值须为 JSON 文本（数组，形状同迁移前 `Vec<PluginQuestion>`）→ 解析为 `serde_json::Value` 透传；非法 JSON 按缺失处理并 `warn`（展示字段不打挂会话链路）
- 单测 5 项：空槽无字段（M2 口径）/ 槽值原样透传 / 空串视为缺失 / `taskQuestions` JSON 解析 / 非法 JSON 降级。

### 2. 内核对任务语义的唯一残留（明示）

`SessionInfoView`（视图类型）+ `task_fields_from_slot`（映射）是内核仅存的「知道这四个对外字段名」的地方：**键名到字段名的机械对应**，不含任何取值语义。线协议若他日收敛为 `annotations` 直出，本映射随之删除（已在两处注释写明）。

### 3. 所有构造点改从槽取值

### 4. 枚举删除

- `enums/session.rs`：`TaskStatus` 枚举 + `Default` impl + 2 项枚举单测删除；`enums.rs` 撤 re-export；留注释说明「任务状值现为槽内不透明字符串」。
- `PluginQuestion`（SDK 侧插件协议类型，经 `enums/plugin.rs` re-export）**保留**：它是插件→宿主→移动端的 `TaskStatusChanged` 同步事件载荷（插件自己的事件，票 15-17 域），不是会话记录的字段。

### 8. 决策与取舍

1. **主库旧会话配置表退役：归收尾票**（票面二选一，此处写明）。理由：`session_configs` 仍有读者——`SessionManager::restart_session`（票 10 的重启执行器）、`create_session_with_source_and_id` / `create_session_no_start`（降级轨与移动端路径）、`host-session.create`（v6，auto-task 定时任务）、宿主配置命令面的降级读写。票 09 只解除了「创建编排」这一条路径，投影与旧表要等这些路径收敛后一并退役。
2. **`taskStatus` 取值口径的既有不一致**（无意观测影响，记录以免误判）：迁移前三条路径转换不同——`sync_handler` 用 `format!("{:?}").to_lowercase()`（`InProgress` → `inprogress`），HTTP/WS 路径走 serde（→ `in_progress`）；而该字段**从未被任何代码写入**（恒 `None`，也无 setter）。contract 后取值以插件写入槽的文本为准（内核不转换），故无可观测回归；插件侧（票 15-17）需统一一种写法。
3. **`SessionInfo` 收窄是编译期证据**：四字段摘除后，任何遗漏的读者都会编译失败——本次仅 `host_impl/session.rs` 与 `wasm_runtime.rs` 两处测试断言需要改（均已按 contract 语义重写）。
4. 移动端零改动：`SessionSummary` / HTTP `SessionItem` / 控制帧字段与序列化形状逐字未变；空槽时行为与迁移前 `None` 一致（M2 降级）。
