### 关键裁决与理由

1. **终端窗口原语而非自建窗口**：spec D3 把「终端窗口 + 宿主布局骨架」列为留内核项；`predictTerminalSize` 与窗口创建规则必须同源（宿主 `terminalInitialSize.ts` 依赖主窗口内容区 ×60% 与字体测量），复制进插件即双份漂移。四个原语全部挂 `session:read`：它们只让调用方「看见并触发宿主既有窗口」，不新增能力语义。
2. **`vue-sonner` 进共享模块映射**：sonner 的 toast 队列是**模块级单例状态**——插件自带第二份则 `toast.success()` 入自家队列、宿主 `<Toaster>` 收不到（实测首轮构建即命中：产物里出现 sonner 内部 `dismissedToasts` 类）。收录判据与 vue/pinia 同类（单例状态），已写进宿主 `shared-runtime.ts` 与 SDK README。
3. **默认值口径（缺陷已知，归票 14）**：宿主版「新建配置默认值」读宿主设置 `settings.session.default_*`；插件读不到宿主设置（`host-config` 白名单不含会话默认值），本票以**插件存储 `session.formDefaults`（上次成功保存值）+ 平台默认环境**承接。宿主设置分组的会话默认值迁移（spec D6 的「设置分组」）归票 14，届时真源统一。
4. **WSL 枚举走既有 interface 追加**（spec D2「缺口一律在既有 interface 上追加函数」）：`host-platform` 无权限门（与选源对话框同口径），故无五同步点扩面；仅 SDK trait 新增方法使 file-transfer 的测试 `MockHost` 需跟演。
5. **兜底壳保留宿主命令面**：`start_session` / `kill_session` / `delete_session` 在插件未激活时走票 09/10 的桥接降级路径，因此兜底壳不需要第二套编排。
6. **插件页页码工具栏扩展点**：宿主原页的 `<PluginPageToolbar target="sessions" />` 挂载点随页面让位消失，插件页无法渲染宿主组件；该贡献面对「会话页」的语义归票 18 复评（当前无插件注册该 target）。
