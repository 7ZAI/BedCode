**两处修正（本会话复核对侧半成品时发现）**

1. **让位判据由「order 区间」改为「同 order 值」**。原判据 `[item.order, item.order + 100)` 让「插在设备配对与会话之间的第三方新域目录」（如 order 150，仓库既有测试即此形态）误判为接管设备域、摘掉宿主「设备配对」入口。改为同槽位精确匹配后：接管方把该域目录落在与内置项相同的 order（D6：设备 100 / 会话 200，同域其余项如连接历史取 101+），插队方不误伤。判据与两侧注释、`SidebarPanelDescriptor.order` 文档同步更正。
2. **懒激活成功路径不得登记激活前的快照状态**。`pluginLoader.activate(id)` 的 `manifest` 取自 `plugin_get_info`（**在** `plugin_activate` **之前**），其 `state` 仍是 `Loaded`；`loadInline` 成功分支原样 `setPluginState(manifest.state)` 会把刚激活的插件判为「未生效」——深链懒激活路径上贡献目录不出现、内置入口不让位、设置分组不渲染。改为登记 `{ state: 'Activated' }`（成功分支的构造性事实）。启动期 `loadRustTsPlugin` / `loadFrontendForAlreadyActivated` 的 `manifest.state` 本就是后端当前态（Activated/Degraded 才放行），保持原样。
