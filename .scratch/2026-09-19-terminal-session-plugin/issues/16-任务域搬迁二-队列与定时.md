### 2. 声明面选择：新增 `contributes.httpEndpoints`（用户裁决）

今天唯一的端点声明面是 `contributes.toolProviders`，宿主 registry 用它生成
`/api/plugin/{id}/{endpoint}` 全路径。复用它零新契约，但代价是把 17 条业务端点标成
「工具提供者」——插件管理页会显示 chip「工具提供者 (17)」，语义错误且不可解释。
故选**新增字段**：`httpEndpoints` 与 toolProviders 共用同一张注册表（冲突照样按属主
仲裁、路由照样精确匹配），只分开语义与展示。SDK 侧纯增量（serde default），**不动
ABI**（本票无 WIT 变更），SDK 包版本不 bump（与票 07–15 同口径，发布走
`docs/knowledge/sdk-publish.md`）。`manifest-gen.js` 的 `{...manifest.contributes}`
合并方式天然保留新字段，已实测。

判据形状固化为四条用例：命中放行、未命中 404、**声明路径不得前缀匹配**
（`/task-status` 不能放行 `/task-status/extra`）、大小写不敏感不成立。

### 3. 表名统一：迁移必须**先于建表**（本票唯一的静默风险点）

统一清单（`schema::TABLE_RENAMES`）：`session_mapping→task_session_mapping`、
`session_settings→task_session_settings`、`preset_tasks→task_preset`、
`scheduled_jobs→task_scheduled`；`task_history` / `task_queue` / `session_configs` /
`plugin_meta` 本已合规。

`activate` 顺序因此重排为：**先 `schema::migrate_via_host()`，再 config / task 建表**。
先建后改会让统一名以空表先占位，迁移遇到「新旧名同时存在」按不破坏原则跳过该条，
旧表的真实行留在无人读的名字下——现象是升级后列表变空而不是报错。该顺序约束写进
`task::ensure_schema_via_host` 与 `schema` 模块文档，并有 `ambiguous` 上报形态兜底。

形状按用户裁决取**可逆重命名 + 账本**：`plugin_meta` 记 `old→new`，
`rollback_to_legacy_names` 据此逆向改名（零复制，不 drop 任何东西）。不建旧名视图：
实测 SQLite 普通视图不可写（`INSERT` 报 `cannot modify ... because it is a view`），
要可写就得给四张表配 12 个 `INSTEAD OF` 触发器，且旧构建的
`CREATE TABLE IF NOT EXISTS` 撞上视图名会直接报错。坏账本在任何改名**之前**显性失败
（不留半途迁移的库）。

另外：`ALTER TABLE RENAME` 不改索引名（实测 `idx_session_mapping_session` 仍挂在新表
上），迁移随手清掉非 `sqlite_autoindex_*` 的旧索引，新索引由各域
`CREATE INDEX IF NOT EXISTS` 建回。

### 4. 旧前缀兜底：实现与代价（切断判定输入，留给票 17）

实现：`resolve_http_owner(请求前缀, 请求前缀已激活, 别名, 别名目标已激活)`。
**旧插件在位时绝不抢占**——双轨期 auto-task 仍写它自己的私有库，若把它的请求转给
合并插件，同一份数据出现两个写者且回包来自空库（读到的队列恒为空，比 404 更坏）。
只有旧插件确实不在位（停用 / error / 未激活）且新插件已激活才接管，`path` 段原样透传
（两侧分派表逐字同形，插件侧零改动）。

代价评估：
- 改动量：宿主一张别名表 + 一个纯函数，约 30 行。收益：移动端与已写入用户项目的旧
  hook 副本零改动即可继续打到桌面。**切断的代价** = M1（移动端任务面板 7 个调用面
  404）+ 用户项目里 `.claude` / `.codex` / `.pi` / `.opencode` 的集成立即失效。
- 审计歧义：日志需要两个字段才说得清「谁在应答」（`plugin_id` = 属主、
  `requested_plugin_id` = 请求前缀），且旧路径在 auto-task 退役后仍是可路由面，排查时
  容易误判旧插件还在。已写进 `docs/knowledge/plugin-http-endpoint-trust.md` §3。
- 本票建议：**票 17 保留兜底**（切断只省一张别名表，换来两端可见行为立刻破损），
  切断时机随移动端适配专项定；判定归属仍在票 17。

### 5. hook 脚本：随包接线落本票，**模板版本 bump 落票 17**

4 个脚本复制进 `plugins/session/scripts/`（auto-task 那份保留到票 17，双轨期两个插件
各自部署各自前缀的副本），脚本内 `PLUGIN_ID` 改指 `com.bedcode.session`；`build.js`
复制时压平一级路径（`hooks.rs` 取的是 `<resource_dir>/<脚本名>`，不是 `scripts/` 子目录）。
契约用例 `shipped_hook_scripts_point_at_this_plugin` 锁三件事：SDK 脚本名常量 ↔ 随包
文件名、脚本含新 id 且不含旧 id、端点拼接形状仍在声明清单里。脚本**文件名不变**——
`cleanup` 与「不误伤用户 hooks」的判定按文件名匹配，改名会让旧条目永久残留。

**故意不在本票 bump `*_TEMPLATE_VERSION`**：双轨期两个插件各自比对自己那份常量，一侧
bump 会让另一侧把项目里的副本改回自己的前缀，出现来回覆盖（最后一次写的人决定 hook
打到哪个前缀）。版本 bump 属 contract 步：票 17 退役 auto-task 后一次性 bump 四个，
把已部署副本改指新前缀。该决定写进了用例文档，防止后人「顺手补上」。

### 6. 广播面对照的做法与边界

做法是**源码逐构造比对**：从两侧 `state.rs` / `queue.rs` / `scheduled.rs` / `preset.rs`
按标记（四个 `SyncEvent` 变体 + `bus_publish(` + `emit_event(`）抓完整构造文本，折叠
空白、统一引号后排序比对，24 组全部等值；再按类钉死触发点数（任务状态 4 点、模式
2 点、队列 1 点、定时 1 点），防「两边同时漏掉一类」的假绿。

它比对的是形状与点数，不是运行时时序——时序由票 15 的
`test_session_task_domain_closed_loop`（输入提交 → in_progress → 注解槽 → Stopped →
interrupted）与本票 HTTP 闭环承担。**auto-task 退役时本用例必须删**（对照基准随旧实现
消失），已挂进票 17 清单。

顺带两处与搬迁前的刻意偏离，都已就地记由：
- 静默看门狗从 `handle_scheduler_tick` 的第 4 步拆成 tick 分发表的独立域：单域失败
  不再连带跳过其它域（D7），一轮 tick 内各步仍恰好一次。
- `recover_creating_jobs` 改为返回受影响数（旧实现内部记日志），日志点归 `activate`，
  私有库不可用时冒泡 `Err` 只降级定时域。
- 定时域内部：每步 DB 失败按步登记、不短路后续步（保持搬迁前「所有步骤都执行」），
  但整域不再 `.unwrap_or(-1)` 静默成「本轮没有到期任务」——改由 tick 分发表计失败。

### 8. 发现的既有断裂：release 构建路径会写坏本插件 manifest

`pnpm run plugins:build`（= `scripts/plugin-build.js`，CI / 发布路径）构建前会跑
`manifest-gen.js` 按源码自动填充。对 `com.bedcode.session` 它做了两件坏事：

1. 前端扫描遇到 `id: panel.id`（循环注册，值来自常量表）解析不出 id，仍写回一条
   **缺 `id` 的 view 条目** → 宿主 `get_manifest()` 反序列化 panic
   （`missing field 'id'`），插件根本加载不了。本票已加防御：解析不出 id 的注册**跳过并
   warn，保留 plugin.json 既有声明**（`manifest-gen.js`）。
2. 命令扫描把 `invoke_command` 的**全部**匹配臂当命令声明，把既定 28 条扩成 56 条
   （`session.trust.*` / `session.config.*` / `session.pairing.*` 等宿主桥接与闭环调试
   臂被当成用户可见命令声明）。这与票 13–15 的手工 pin（四处同步）直接冲突。

第 2 点本票未动判定（不属本票范围），已作为清单第 9 项写进票 17：要么让 manifest-gen
只补「未在 manifest 出现」的臂并保留人工裁剪，要么把 56 条定为最终事实并改全部 pin。
**在收口之前，本插件产物只能用 `node plugins/session/scripts/build.js` 构建**（票 03–15
实际用的就是这条路），发布路径待票 17——这也解释了为什么票 03 的「构建白名单收编」
没暴露该问题。
