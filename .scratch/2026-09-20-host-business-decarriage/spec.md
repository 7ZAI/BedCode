## Problem Statement

1. **宿主侧仍滞留四块完整业务**：领域审计（2026-09-20）确认——git 分支/checkout（已注册 HTTP 路由但桌面与移动端均无消费方，僵尸模块）；本地文件浏览（文件树/内容/diff，移动端活跃使用）；快捷指令（主库表 + HTTP + WS 服务 + 桌面命令面 + 同步广播全链路活跃，session 插件三域不含它）；对等网络传输编排（发送/接收/远端浏览约 4000 行，托管在宿主侧而全部引擎原语已在 `host-peer`）。
2. **同一事实出现双轨数据源**：会话配置真源已迁插件私有库（票 08，桌面命令面薄转发），但移动端 HTTP 查询面仍直读宿主主库 `session_configs` 表——「同一份会话配置」桌面端与 HTTP 面各答一版，存在漂移风险。
3. **传输编排滞留在原语与插件就位之后**：`host-peer` 原语已覆盖拨号/收发/收发策略/共享根/浏览/拉取 + `peer:*` 消息总线推送事件，WIT 契约注释明示「file-transfer 插件是首个上层消费者」，设置键也已迁插件——**唯独编排逻辑本身没搬走**，设计意图悬空。
4. **宿主路由面拖着无消费者业务**：git 业务以僵尸形态挂 HTTP 路由，审计面失真（分不清哪些是引擎端点、哪些是残留业务）；`quick_actions` 等业务表仍由宿主主库真源持有。
5. **与「无业务内核」终态仍有实质差距**：认证链与命令面桥接是设计内保留，但上述业务块每多留一天，宿主发版影响面、安全面、插件化演进面都多一块需要单独评估的债务。

## Solution

**宿主只保留基础服务与插件核心**：进程（PTY）引擎、网络引擎（HTTP/WS 通道、peer-net 连接与传输引擎、mDNS 基础服务）、存储引擎、安全边界（JWT 签发/验签执行点、密钥托管、信任与表）、消息总线、wasmtime 运行时、插件核心（注册表/权限/能力/路由），**以及一个新增的「HTTP 协议网关」基础服务**；业务代码=0。

**HTTP 协议网关**（新增平台基础服务，不含业务语义）：宿主维护一张「对外业务 URL → 目标插件」别名路由表（`/api/configs`、`/api/quick-actions`、`/api/file-*`、`/api/git/*`），按表把移动端请求转发到目标插件的 HTTP 端点；**验签仍在宿主中间件统一执行**（移动端 JWT 在转发前校验），插件收到的是可信上下文；复用既有插件动态 HTTP 端点代理的转发内核，不发明新传输机制。URL 与响应 JSON 形状**逐字节不变**——移动端零改动是硬约束。

**四块业务按归属下沉**：
- 配置域（会话配置 HTTP 查询面收编，消除双轨）+ **快捷指令**（第 4 域）→ `com.bedcode.session`
- **本地文件浏览**（文件树/内容/diff）→ `com.bedcode.session` 工作区/文件浏览域（host-fs + fs_auth 三层校验接管路径越界防护）
- **git**（僵尸 → 复活为组件化能力）→ `com.bedcode.session` 工作区 git 域（host-process 非交互 + host-fs）
- **传输编排**（发送扇出/进度/历史/重试、接收策略/落点、远端浏览编排）→ `com.bedcode.file-transfer`（rust 后端，host-peer 原语 + `peer:*` 总线 + 插件存储持久化）

**失效策略**: 业务数据真源进插件后**宿主不再持有业务副本**——目标插件未激活时网关返回明确的「插件未激活」错误（业务端点不存在降级旧实现；认证/终端等引擎端点不受影响，底座仍可跑其他插件）。这与既有「命令面薄转发 + 降级宿主」范式在业务数据上不同：配置/快捷指令/文件浏览/传输历史是**业务数据**，宿主不留副本符合无业务内核红线，禁用插件时业务端点应清晰报错而非返回假数据。

**全网关收编后**：宿主 HTTP 面 = 引擎端点（auth/ws/health/plugin/static）+ 网关；`session_controller`（/api/sessions）保持现有壳形态不动（已注解槽感知、无业务实现，属引擎协议面）。

用户视角：外观、行为、协议形状全部不变；变的是实现位置与发版口径（业务规则改插件工程即可，不必发桌面宿主）。

## User Stories

### 桌面主机用户

1. 作为桌面主机用户，我希望升级后侧边栏、设置页、终端手感与今天完全一致，以便感受不到这次重构。
2. 作为桌面主机用户，我希望配置、快捷指令、文件浏览、git 能力的行为与今天逐项相同，以便无感迁移。
3. 作为桌面主机用户，我希望历史数据（会话配置、快捷指令、传输历史）迁移后一条不丢，以便升级零损失。
4. 作为桌面主机用户，我希望禁用 session 插件后应用不白屏、底座功能仍可用，业务端点给出明确「插件未激活」提示而非假数据，以便试验插件开关没有心理负担。
5. 作为桌面主机用户，我希望 git 分支/checkout 这类能力在插件 API 面可直接复用，以便未来加界面时有落点。

### 移动端用户

6. 作为移动端用户，我希望 `configs / quick-actions / file-tree / file-content / diff-tree` 查询的 URL 与响应形状与今天逐字节一致，以便桌面端改造后移动端零适配成本。
7. 作为移动端用户，我希望 WS 同步广播（快捷指令等变更）形状不变，以便现有订阅逻辑零改动。
8. 作为移动端用户，我希望会话列表/会话控制协议面（`/api/sessions` 与 WS 通道）不动，以便远程终端主路径完全不受影响。

### 插件维护者 / 插件作者

9. 作为 session 插件维护者，我希望配置域、快捷指令域、文件浏览域、git 域在同一插件内聚（共享会话/工作区上下文），以便一个插件交付完整的「终端会话 + 工作区」闭环。
10. 作为 file-transfer 插件维护者，我希望传输编排（发送/接收/暂停/恢复/历史/策略）在插件侧实现，以便能力可独立演进、复用与发版，不必改桌面宿主。
11. 作为第三方插件作者，我希望宿主 HTTP 网关按「业务 URL → 插件」别名表工作，以便我的插件可声明对外业务端点而无需新建宿主路由。
12. 作为插件作者，我希望插件禁用/启用不影响引擎端点与已加载插件的互调，以便编排可安全试验。

### 发布经理 / 安全审计者

13. 作为发布经理，我希望宿主发版清单里不再出现 git、文件浏览、快捷指令、传输编排这些业务模块，以便发布影响面变小、变更可追溯。
14. 作为安全审计者，我希望宿主 HTTP 面只含引擎端点与网关，业务校验（路径越界、目录访问、git 参数）落在插件 fs_auth/权限链上，以便安全边界可审计。
15. 作为集成测试维护者，我希望每条业务契约被「双轨对照」锁定，以便任何实现位置切换都有回归网兜底。
16. 作为审计者，我希望主库表面收敛到引擎表（信任/连接历史/插件存储/插件密钥/引擎设置），业务表（会话配置、快捷指令）不在宿主契约内，以便数据面可审计。

## Implementation Decisions

1. **HTTP 协议网关（新增平台基础服务，T1 先行）**
   - 宿主持有静态别名路由表：`/api/configs`、`/api/quick-actions`、`/api/file-tree|file-content|diff-tree|file-diff`、`/api/git/*` → 各自目标插件与端点路径。
   - 转发复用既有插件动态 HTTP 端点代理（`/api/plugin/{plugin_id}/{path}`）的同一转发内核与信任判定（`plugin-http-endpoint-trust` 文档化语义），仅前缀不同并附加别名解析；不新增传输机制。
   - 鉴权：移动端 JWT 验签仍在宿主统一中间件完成（验证权留宿主，沿用认证红线）；转发时透传可信设备上下文给插件，插件侧自行裁决自身业务权限（不重复验签）。
   - 双轨起步：别名目标未实现/未激活 → 降级宿主旧实现；对外形状与今天逐字节一致；所有业务端点契约测试先于任何域名切换落地（T1 交付即锁死形状）。
   - 目标插件激活时网关即切插件路径；宿主旧实现仅在插件不可用且仍有宿主数据面时作为降级（T2-T4 各自在插件面无缺口验收后退役宿主实现，见决策 3）。

2. **`/api/sessions` 不进网关收编**：`session_controller` 已是注解槽感知的宿主命令面壳（无业务实现），保持壳形态；本规格只收编仍含业务实现的端点。

3. **业务数据真源进插件、宿主不留副本（宿主表退役为 contract）**
   - 配置/快捷指令真源 = session 插件私有库；传输历史/策略真源 = file-transfer 插件存储。
   - 宿主主库 `session_configs` / `quick_actions` 业务段退役：先双写对照（插件真源 + 宿主旧面同时验形状），迁移验收（幂等：旧库重跑、历史可回溯）通过后删除宿主表契约与宿主实现（contract 步骤，可回滚仅剩 git revert）。
   - 僵尸 git 模块：路由与 DTO 退役，能力以插件 API 形态复活（含契约测试锁定非 git 仓库语义）。

4. **session 插件扩展域（T2/T3/T4）**
   - 快捷指令 = 第 4 域（私有库表，沿用插件存储隔离规则）；
   - 文件浏览 = 工作区/文件浏览域：host-fs + fs_auth 三层校验（路径白名单 → 插件白名单 → 弹窗授权）接管 `../` 穿越拒绝等安全语义，安全强度不低于现宿主实现；
   - git = 工作区 git 域：host-process（非交互进程原语）+ host-fs，命令语义（分支/status/checkout、非 git 仓库判定）与现契约一致；
   - 对外面：HTTP 经网关（httpEndpoints 清单声明 + 插件分派表同源锁定）；WS 同步广播（快捷指令变更）经 host-events.broadcast-sync 由插件触发，宿主同步处理器中对应业务形状段落退役。

5. **peer 传输编排下沉（T5 expand / T6 contract）**
   - file-transfer 插件 rust 后端新增传输编排域：订阅 `peer:*` 总线（devices/connection/consent/transfer/receive）驱动前端状态；发送扇出/取消/重试、接收策略/落点 CRUD、历史持久化全部在插件侧（host-peer 已覆盖全部所需原语，**无需新增宿主原语、无需 WIT/ABI bump**，desktop WIT 保持 v19）。
   - 宿主侧编排与事件桥（进度节流转发、历史文件落盘）保留为双轨降级，T5 验收（双轨对照 + 真实 wasm 闭环 + 历史迁移幂等）后 T6 删除宿主编排、命令面与事件桥，宿主仅留 peer-net 引擎接入（节点身份/守护/连接表）。

6. **不新增 host 原语、不触发 ABI bump**：全部下沉经既有 `host-peer` / `host-fs` / `host-process` / `host-events` / `host-bus` / `host-plugin-database` 完成；网关复用既有转发内核。唯一宿主新增代码 = 网关别名路由表与契约测试。

7. **i18n / 前端零改动**：前端测试锁定 invoke 契约，桌面 UI 与移动端均不改（业务规则文案随插件工程走既有 i18n 命名空间规范）。

## Testing Decisions

- **唯一主接缝：对端契约形状**（沿用终端会话中心规格的用户决策①）：下沉前后 HTTP 端点 JSON 形状、invoke 命令签名、WS 同步广播形状**逐字段不变**。契约测试以「双轨对照」形式落地（同一请求新旧两条实现路径输出一致），先例：`pairing.rs` 双轨对照测试、`test_server_auth_policy_closed_loop`（真实 wasm 闭环）、`ws_auth_rules`（真实 WS 集成）。
- **插件域 seam**：每个新域 native 契约测试（正例/反例/边界，遵循 unit-test-discipline）+ 真实 wasm 构建防漂移 + httpEndpoints manifest 与插件分派表同源锁定的契约用例（先例：devices 71/0、session 123/0、wasm 产物防漂移脚本）。
- **迁移幂等测试**：旧库重跑、历史文件/表数据重入迁移必须幂等，锁「升级一无感」。
- **安全测试**：文件浏览域的路径越界拒绝（`../` 穿越、symlink 逃逸）在插件 fs_auth 链上的单测；git 非仓库语义（404/降级判定）契约测试。
- **只测外部行为，不测实现细节**：测试断言取决于「对外形状与权限结果」，不依赖「实现位于宿主还是插件」。
- 前端测试零改（invoke 契约锁定者）。

## Out of Scope

- **移动端零改动**：`bedcode-mobile/` 一个文件不改；移动端「调用桌面端」的既有路径因桌面侧实现位置变化不产生协议影响（形状不变），移动端适配无立项。
- `/api/sessions` 壳形态、WS 终端通道（TB v3 帧、控制帧、resync）、认证链路（签发/验签/密钥托管/trust 表）与 auth 中间件：保持现状不动。
- 终端渲染/输出分发管道与 `pty/*` 引擎：留内核（roadmap 阶段 3 终端部分，另行立项）。
- peer-net 引擎本体（连接/握手/chunk/加密/token 语义）与节点身份/发现守护：留宿主。
- 新增宿主原语或 WIT ABI bump：明确不引入（v19 保持）。
- AI 域（`ai-chatbox` / `agent-hub`，已插件化）与移动端插件（`auto-task` 等）：另账。
- 移动端「禁插件降级」的运行时排障：不在本规格。
