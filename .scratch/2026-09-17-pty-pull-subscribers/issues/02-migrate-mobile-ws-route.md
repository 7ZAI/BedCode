# 02: 移动端 WS 订阅切到拉取模型（tracer bullet）

**What to build:** 移动端终端链路**整条**跑在拉取模型上（环 → 订阅者执行体 → WS → 客户端），并证明「一个不 ack 的慢订阅者不再冻结链路」——这是本方案的核心用户可见收益：桌面本地终端与 PTY 产出照常，移动端自己最多被截断（可自愈，见 05），而不是让所有人一起卡死。

**Blocked by:** 01 — 拉取模型订阅者（expand）

**Status:** done (2026-09-17)

- [ ] 移动端路由的订阅、ack、退订、重订阅全部由订阅者执行体承担；该路由不再参与旧的占位/待发缓冲路径
- [ ] 帧序对客户端不变：历史 → 边界标记 → 实时；断线重连按游标续传（保留既有续传语义）
- [ ] 模式切换（实时/批量）即时 flush 残留批次
- [ ] **回归护栏**：一个订阅者永不 ack 时，桌面本地终端仍持续收到输出、PTY 读产出不中断（对照现状的会话冻结）
- [ ] 客户端侧既有行为不退化：历史拼接、跨帧裁剪、去重、游标推进（移动端既有测试全绿）
- [ ] 文档：链路图更新为「三段式（源 / 环 / 每订阅者游标）」，并标注本路由已迁移
