# 06: 三段容量/水位预算对齐

**What to build:** 链路现在有三段缓冲，各段的容量与水位的相互关系决定「什么时候该驻留、什么时候会被截断」。本票把这张预算表明确下来并落到常量与断言上，消除两类隐性故障：

- **上游缓存小于下游**：下游还没到驻留点就已经被上游淘汰 → 无谓截断（用户看到清屏重播）
- **阈值组合互相锁死**：客户端 ack 阈值 ≥ 订阅者高水位 → 订阅者永远等不到能解锁的 ack → 驻留到僵尸回收

同时按新语义重定移动端 ack 阈值（放宽以减少 ack 帧数），其上界由**客户端 WS 接收缓冲**决定（沿用既有约束：水位必须低于接收缓冲，否则溢出丢消息）。
