# 01: 拉取模型订阅者（expand）

**What to build:** 每条终端订阅链路拥有自己的独立执行体，持**位置指针**在会话输出环上循环读取并转发；它有自己的 ack 水位与窗口节流，落后只影响它自己。

本票只落地「并存形态」——新订阅者执行体与其依赖的环读取能力可用、被单测覆盖，**既有推送路径不动**，链路保持全绿：

- 先做前置改造：为环补上「按游标零拷贝读取」（返回单块、块内裁头、起点早于驻留起点时明确返回"已淘汰"而不是残缺数据）与「驻留水印读取」；把转发路径里的合帧决策抽成可独立测试的纯决策单元，**新旧路径共用同一实现**（既有转发行为与实时/批量双速语义不变）。
- 再做主体：订阅者执行体按位置指针推进，按实时/批量两档合帧，窗口（已推进游标 − 客户端 ack）越位即驻留等待，窗口回落后继续；订阅起点早于驻留起点时产出「需要重同步」信号（本票只产信号，协议见 05）；订阅从一开始（无历史可发）也必须发出历史边界标记，否则客户端等不到边界会卡到超时。
- 订阅者的水位/驻留轮询/僵尸超时可配置（默认值见 spec §8）；僵尸（窗口长期不降）被回收并留痕。

**Blocked by:** None (can start immediately)

- [ ] 合帧决策成为可独立测试的纯决策单元，新旧转发路径共用，既有双速语义与帧头区间=负载的契约不变（既有测试全绿）
