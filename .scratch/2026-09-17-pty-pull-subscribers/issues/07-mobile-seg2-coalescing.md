# 07: 移动端段2 合帧

**What to build:** 移动端「Rust → 前端」这一段（段2）目前逐帧推送事件。未渲染窗口内的连续帧可以合并成更少、更大的事件，直接减少 WebView 侧的事件分发次数与 base64 解码次数——这是段2 唯一还剩的固定开销，且与设备性能无关地线性放大。

约束：只合并**连续**区间；跨字节洞不合并（消费端的缺口判定语义必须保持）；段2 既有的订阅门控、水位滞回、恢复补推语义一律不退化。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 未渲染窗口内按字节窗合并连续帧为单个事件推送；事件数与解码次数按合并比例下降（给出合并前后每 x KB 的事件数对比）
- [ ] 合并仅限连续区间：跨洞切分，消费端"帧首越过游标 = 缺口"判定不变
- [ ] 段2 既有语义不退化：订阅门控（未订阅只入缓存）、水位滞回（越位停推）、恢复补推（按连续段）全部保持
- [ ] 移动端 `pnpm run test:run` 全绿，新增合并行为单测（连续合并 / 跨洞切分 / 水位下合帧上限）
- [ ] 真机验证：TUI 高频重绘下滚动无新增残影/错行（合并不得改变写入顺序）

参见 spec 第 7（M5）节。
