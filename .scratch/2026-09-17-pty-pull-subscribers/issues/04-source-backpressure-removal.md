# 04: 源侧去背压 + 旧机制下线（contract）

**What to build:** PTY 读路径回归"只读 + 入环"的本职，**不再承担任何背压**；随之下线一整套为「在源侧做流控」而存在的机制，净减复杂度。

删除范围（两条路由都已迁移后才可执行）：

- 源侧的背压判定与轮询暂停
- 会话级共享未 ack 记账（与其 FIFO 容量、冲正、滞回水位）
- 订阅者占位/待发缓冲（pending）与其容量上限
- 阻塞式广播（有界等待发送 + 发送超时 + 冲正）
- 旧的两级「订阅通道 + 转发循环」plumbing（合帧与双速已归入订阅者执行体）

**Blocked by:** 02 — 移动端 WS 订阅切到拉取模型；03 — 桌面本地终端订阅切到拉取模型

**Status:** done (2026-09-17)

- [ ] PTY 读路径不含任何背压/暂停判定（编译期即可保证：相关 API 已删除）
- [ ] 读产出速率不受消费者影响：慢订阅者/零订阅者下产出字节持续增长（测试断言）
- [ ] 上述五类旧机制全部删除，无残留调用点与死代码
- [ ] 相关测试迁移到订阅者侧语义（窗口门控 / 驻留 / 隔离），不保留"源侧暂停/恢复"用例
- [ ] 桌面 `cargo test` 全绿；无告警新增
- [ ] 文档：pipeline 文档同步"背压归属"表（源不参与 / 每订阅者私有 ack / 三段容量）
