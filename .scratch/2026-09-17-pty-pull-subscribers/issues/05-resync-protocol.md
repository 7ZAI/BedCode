# 05: Resync 协议（两端）

**What to build:** 订阅者游标落后于环驻留起点（长期驻留 / 客户端断网后游标过旧）时，把"截断"从一种**隐性的、看起来像卡死的**状态，变成一条显式信号 + 可自愈的恢复流程：

- 桌面下发显式重同步信号（携带新的驻留起点与当前快照点），随后从驻留起点连续重播；
- 桌面本地终端：清屏 → 以新锚点重建游标 → 用户提示（每订阅者一次）；
- 移动端：消费该信号，走「清屏 + 锚定重播」，取代间接的「缺口 → 重拉历史」往返；**保留间接路径作为兜底**（老端/信号丢失时不退化）。

老客户端忽略未知帧后行为不变（只增不改），两端同步部署。

**Blocked by:** 01 — 拉取模型订阅者（expand）；02 — 移动端 WS 订阅切到拉取模型

**Status:** done (2026-09-17)

- [ ] 桌面本地终端消费该信号：清屏 + 重锚 + 提示（同一订阅者一次截断只提示一次）
