# 2026-10-13 桌面端前端宿主界面重构 — 方案 C：设备壳（主屏 + 卡片切换）

> 定位：与 `shell-preview.html`（方案 A · 标签页工作台）、`shell-preview-b.html`（方案 B · 分屏平铺工作区）
> 并列的**第三个候选方案**。隐喻取自 Android 设备模型的**一半**：主屏图标点开应用、应用全屏、
> 打开过的东西以卡片呈现可切换；**不照搬另一半**（无时钟日期小组件、无底部三键导航条、
> 无全宽下拉抽屉）——导航收进顶部工具栏，系统页面参照方案 B 的管理中心设计。

## 修订记录

- **v0.1**（2026-10-13 初版）：全盘 Android 化——状态栏时钟、底部三键导航条、全宽通知抽屉、
  recents 覆层、系统应用独立入口。
- **v0.2**（按用户反馈改版）：
  1. **去时钟/日期**——主屏不再有时间日期小组件，工具栏也无时钟（桌面系统本就有时钟）；
  2. **导航栏收进顶部工具栏**——底部三键导航条删除，返回/主屏按钮进顶部工具栏
     （与品牌、当前位置、全局入口、窗口控制同行）；
  3. **系统页 = 卡片**——设置/应用管理/权限与授权不再是独立「系统应用」形态，而是与业务应用
     **同构的卡片**：主屏网格点开 → 全屏 → 进主屏卡片带，与业务应用一起切换/关闭；
  4. **home = 卡片总览**——主屏顶部是「正在运行」卡片带（打开中的应用与系统页，MRU 排序），
     点卡片切换、× 关闭，不再需要独立的 recents 覆层；
  5. **系统页内容参照方案 B**——管理中心三页的密度与结构（标准圆角卡片、左列表右详情、
     分段控件、四分区记录）直接沿用，只换承载壳；
  6. 通知抽屉从全宽 Android 抽屉改为工具栏锚定的下拉面板（快捷开关 + 通知）。
- **v0.3**（按用户反馈增强）：
  1. **主屏壁纸**：设置「背景」组提供 无 / 极光 / 沙丘 / 礁湖 四张 token 派生渐变壁纸 +
     自定义图片入口（预览不读盘，正式实现走 `fs:pick` 授权）。壁纸只落主屏；卡片全屏保持
     纯色保证业务内容可读。壁纸上盖一层页面色遮罩（强度 0–70% 可调）护文字对比度。
  2. **导航按钮可显隐**：设置「界面」组新增「导航按钮」开关，关闭后顶部工具栏的
     「返回 / 主屏」消失（Esc 始终可用）；其余工具栏入口不受影响。
  3. **卡片式通知中心**（参考手机系统通知栏）：通知面板升级为通知中心——快捷开关 2×2 +
     「待处理」区（审批通知，动态派生自 approvalIds，批准后自然消失、无独立生命周期）+
     「通知」区（事件/进度/信息卡片：来源图标 + 标题 + 相对时间 + 内容 + 动作行 + 单条关闭）。
     进度通知带进度条；「清除全部」只清非驻留项；铃铛角标 = 全部条目计数；
     生命周期事件（停用 / 批准 / 全部关闭）自动落事件通知。

### 自审发现并已修的缺陷（v0.1 → v0.2 过程中）

1. **暗色主题从未生效**（v0.1 遗留）：`<body class="dark">` 挂错节点——`style.css` 的选择器是
   `:root.dark`，类必须在 `<html>` 上。几何审计抓不到（颜色不算 violation），靠计算样式断言
   钉住（`getComputedStyle(body).backgroundColor === rgb(21,19,15)`）。
2. **v0.1 recents 方向键空 MRU 越界**：`Math.min(cur+1, n-1)` 在 0 张卡时得 -1（v0.2 已随
   recents 覆层一并移除，命令面板方向键保留双向钳位写法）。
3. **change 事件兜底监听在 select 上抛 TypeError**：`data-act-inp` 控件没有 `data-act`，
   `.startsWith` 抛错。该监听本是死代码（click 已覆盖），删除而非补判空。

### 已知边界（明示，非缺陷）

- **type-to-search 不支持 IME 合成中的 CJK**：全局 `keydown` 收不到合成事件。原型用 ASCII
  验证路径；正式实现应挂隐藏 input 或监听 composition 事件。命令面板的 CJK 过滤正常
  （走真实 `<input>` 的 input 事件，已验证）。
- **卡片缩略是静态副本**：应用卡渲染 mock 内容的 `inert` 副本，系统页卡渲染骨架条；
  正式实现的真源是视图离屏渲染或 `PluginViewHost` 只读镜像，不引入截图管线。
- **同一应用单实例**（同方案 B 待决策 6，多开需 WIT 寻址维度变更）。

## 关键设计决策

### 1. 两屏模型 + 卡片 MRU（不是屏幕栈）

```js
state.screen: 'home' | 'card'           // 只有两屏，无栈
state.cards: ['app:terminal-session', 'sys:settings', ...]   // MRU，最新在前
state.activeCard: 'app:ai-chatbox'      // card 屏显示哪张卡
```

- **开卡**：点主屏图标 → 有卡直接激活，无卡产卡并置顶 MRU（应用卡先启动实例：
  `dormant → running`；approval 态进审批屏卡）。重复打开只重排、不重复产卡。
- **关卡通配语义**：应用卡 ×= **停用实例**（→ dormant，卡片移除）；系统页卡 ×= 只关页面。
  关的是活动卡 → 切 MRU 次卡；无卡 → 回主屏。「全部关闭」一键清场。
- **系统页与业务应用同构**：主屏系统网格点开 → 全屏 → 进卡片带，与业务卡一起
  切换/关闭——用户要的「设置/权限管理也是卡片」即此。系统页头部保留三页互切 tab
  （切换 = 激活另一张系统页卡，不弹栈）。
- **返回（Esc / 工具栏←）**= 逐层收覆层（dialog > palette > ctx > panel），耗尽后
  `card → home`；主屏上返回禁用（35% 透明 + `disabled`），不做隐藏约定。
- 切屏动效：`scale(0.97)+translateY(6px) → none`，220ms 减速曲线（依据
  `--domain ux` Easing Functions：到达用减速；Cancellable State Transitions：类只是
  装饰，状态先行正确）。`prefers-reduced-motion` 全局压平。

### 2. 反监控看板（用户核心诉求的落实清单）

| 看板风的做法 | 本方案的做法 |
| --- | --- |
| 常驻指标条（CPU/内存/速率/时钟） | 工具栏只有：品牌、当前位置、导航、命令面板、通知铃（待审批计数）、主题、窗口控制——**无时钟无指标** |
| 首屏 = 仪表盘网格 | 首屏 = **主屏**：运行卡片带 + 图标网格 |
| 每面板带状态头/迷你图 | 卡片全屏无宿主装饰，appbar 属于应用内容 |
| 配额/通道数进首屏 | 收进「应用管理 → 详情」与「权限与授权」 |
| 密集小字表格 | 图标 28% squircle 圆角、卡片 16px 圆角、语义整句（`role="status"` 报当前位置，不播报裸指标） |

### 3. 三个系统页（默认全局管理页，参照方案 B 的页面）

| 系统页 | 内容 | 真源对齐 |
| --- | --- | --- |
| **应用管理** | 按风险排序的应用列表（`always_allow` 置顶）+ 详情六块：信息 / 生命周期（启停·卸载二次确认·打开）/ 授权策略两行三档 / 权限位只读 pill（高危标红）/ 应用配置（schema 驱动控件 + 空态说明） | `PluginsView` / `PluginDetailView` / `PluginConfigView` |
| **权限与授权** | 待审批横幅（一键去审批）+ 每应用授权卡：策略分段控件 + 四分区计数 chip + **四分区记录明细**（用户已授权可撤销 / 免询问自动放行带「未经确认」/ 内置免询问只读 / 硬拒绝可撤销） | `AuthorizationView` + `authPolicy.ts` 分区口径 + `first_party_dirs.rs` 清单 |
| **设置** | 界面（主题三档 + 6 色板 + 语言 + 字号滑杆 + 动画）/ 链路加密（主开关 + 4 子开关随主开关 disabled + 指纹）/ 系统（防休眠 + 默认端口 + 授权入口）/ 日志（仅 DEV 标注）/ 关于（版本 + 检查更新 + 弹窗目录 + 重演启动屏） | `SettingsView` 六分组逐项对应 |

密度与结构沿用方案 B 的管理中心：标准 `--radius-card` 圆角、左列表右详情、分段控件、
四分区记录行。语义边界与 B 完全一致（已核对事实）：策略切换不追溯存量记录、整单审批
无逐位勾选、撤销需宿主凭证、卸载先停用、免询问记录强制「未经确认」标、四分区互斥且
完备（有测试钉住）。

### 4. 视觉语言（token-bound 前提下的现代感）

- **零新增 hex、零新字体族**（同 A/B 铁律）。新增 3 个 token（落地时按「3+ 组件复用」
  规则迁 `style.css`）：`--radius-app-icon: 28%`、`--radius-sheet: 16px`、`--toolbar-h: 44px`。
- 应用图标底色全部 `color-mix()` 从既有语义 token 派生（primary/info/success/warning +
  info×success 混色），双主题自动适配；系统页图标统一 `tone-system` 灰底标识系统身份。
- **动效即反馈**：切屏缩放到达、卡片错峰升起（40ms stagger）、图标 hover 上浮 +
  按压 `scale(0.96)`；全部 property-specific、≤300ms、reduced-motion 压平。
- 依据检索：`--domain ux`（easing / cancellable transitions / focus visible / z-index 分层）；
  `--design-system` 的色板字体建议被真源裁决否决（沿用 `style.css` token 与字体栈）。

### 5. 背景图（主屏壁纸）

- **只落主屏**：壁纸是主屏的背景层；卡片全屏（应用视图 / 系统页）保持纯色——业务内容可读性优先。
- **零新 hex**：三张内置壁纸全部是 `color-mix()` 从既有语义 token 派生的渐变
  （`--wall-aurora / --wall-dune / --wall-reef`），双主题自动适配；「无」= 纯 `--bg-page`。
- **可读性护栏**：壁纸上盖一层 `--bg-page` 遮罩（`--wall-dim` 0–70%，默认 30%），
  背景图固定在元素自身（不随内容滚动）。
- **自定义图片**：预览只到入口（toast）；正式实现路径 = `fs:pick` 授权选图 → 宿主读盘下发
  （前端零资源访问红线，见 AGENTS §6）。

### 6. 导航按钮显隐

设置「界面」组 `show_nav` 开关控制工具栏「返回 / 主屏」按钮组。隐藏后仅剩键盘路径
（Esc 全程等效返回）；工具栏其余入口（命令面板 / 通知 / 主题 / 窗口控制）不受影响。
默认显示——导航是发现性入口，隐藏是熟手的收窄选择。

### 7. 卡片式通知中心（参考手机系统通知栏）

- **模型**：`state.notifs`（事件/进度/信息，可清除）+ `approvalNotifs()`（审批，从
  `approvalIds()` **动态派生**——批准后自然消失，不留尸体、无独立生命周期）。
- **卡片结构**：来源图标（tone 底）+ 标题 + 相对时间 + 来源 + 内容 + 动作行 + 单条 ×
  （驻留项与审批项无 ×）。进度通知带进度条。
- **动作**：审批通知「去审批」直达审批弹窗；事件通知「查看/重新打开」直达应用卡。
- **清除全部**：只清非驻留项；驻留（运行时就绪）与待审批保留。
- **角标**：铃铛角标 = 全部条目计数（通知 + 待审批）。
- **生命周期挂钩**：停用应用 / 批准启动 / 全部关闭 自动落事件通知——通知中心是
  宿主事件的可见面，不只是静态列表。
- **归属红线**：宿主只承载机制面（来源/驻留/动作/时间戳），文案由来源方给出；
  宿主不解析业务内容（B4 不命中）。

### 8. 架构红线自检（B1–B6）

壳的数据形状 = 卡片 MRU（机制）+ 注册表投影（机制词汇）+ 授权读模型（机制词汇）。
无产品类型/状态机/真源/投影/业务默认值/产品事件挂钩。系统页的授权词汇是 §5.1.3 ②

## 交互清单（原型内可玩）

- 主屏：点图标开卡（dormant 即点即启、approval 进审批屏卡）；右键图标出上下文菜单
  （打开/详情/权限/停用/卸载）；直接打字搜索（ASCII；Enter 开首个匹配，Backspace 删，Esc 清）
- 卡片带：点卡片切换 / × 关闭（应用=停用、系统页=关页）/ 全部关闭；活动卡高亮描边
- 工具栏：← 返回（逐层收覆层）/ 主屏（可在设置里隐藏）；命令面板 / 通知中心（计数角标）/ 主题切换
- 通知中心：快捷开关 2×2；待处理区（审批通知 → 直达审批弹窗）；通知区（单条 × 关闭、
  动作按钮、进度条、清除全部留驻留）；停用/批准/全部关闭自动落通知
- 设置：界面（主题/色板/语言/字号/动画/**导航按钮显隐**）+ **背景（壁纸四选 + 遮罩强度 +
  自定义图片入口）**+ 链路加密 / 系统 / 日志 / 关于
- 系统页：三页互切 tab（各持一卡）；应用管理全流程（启停/审批/卸载/策略/撤销/配置）；
  权限与授权四分区明细；设置六分组全控件
- 命令面板：`Ctrl+Shift+P`（或工具栏放大镜），CJK 过滤正常，方向键 + Enter 执行
- 弹窗目录（设置→关于 或命令面板）：10 种全局弹窗逐个预览；启动屏可重演
- 快捷键：`Esc` 返回/收覆层 · `Ctrl+Shift+P` 命令面板 · `Ctrl+,` 打开设置卡
- 双主题即时切换（工具栏 ◐ / 设置三档 / 通知面板 tile 三处入口）

## 待决策点

1. **与 A/B 的裁决**：三案并排（A=标签页，B=分屏同屏，C=主屏+全屏卡片）。
2. **同一应用多实例**：需 `appId+instanceId` 寻址维度，WIT 变更走 ABI 流程。
3. **卡片缩略真源**：静态离屏渲染 vs 活快照镜像（涉及 `PluginViewHost` 是否支持双挂载）。
4. **主屏图标排序/分组**：注册表顺序 vs 用户自定义（自定义布局属宿主状态，
   落 `host-storage`——归属问题需用户裁定，同 B 待决策 5）。
5. **通知中心数据源**：现状宿主无统一通知中心；原型用「审批派生 + 生命周期事件」两条
   真源路径演示。是否立「宿主通知面」为正式机制（还是纯事件聚合层）需裁定。
6. **自定义壁纸的正式链路**：`fs:pick` 授权 → 宿主读盘 → 下发为壳资源；授权记录落在
   「宿主」名下还是空挂（不属任何插件）——需裁定。
7. **type-to-search 的 IME 支持形态**（隐藏 input vs composition 事件）随正式实现定。
8. **系统页三页互切 tab 的语义**：当前是「激活另一张系统页卡」；也可选「同一系统卡内
   换页」（卡数更少、MRU 更短）。两种都成立，倾向当前方案（心智一致：一切皆卡）。
