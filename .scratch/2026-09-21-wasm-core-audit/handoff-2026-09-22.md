## 3. 已完成五票：只需知道的结论

- **票 01**：权限词汇唯一真源 = 桌面 SDK `permission.rs` 的 `PERMISSION_VOCABULARY` 反射表，
  两份生成物（CLI json / 前端 ts）由 `pnpm run gen:permissions` 重出；宿主 `plugin/permission.rs`
  五条锁 + 前端五组锁，**加/拆权限位漏跑生成器即转红**。
  后置项（展示文案只覆盖 13/31）是**票 03 的前置子项**。
- **票 02**：主库 SQL 边界从正则挪进 SQLite authorizer（`with_main_db_guards`），
  `storage` 不再自动授予，新增高危位 `database:main`；`validate_sql_table_prefix` 只是早失败文案。
  登记了一条**未修的既有缺陷**：`reject_bare_transaction_control` 会把
  `CREATE TRIGGER … BEGIN … END` 误判成裸事务控制 → 主库面触发器不可用（见票 02「过程中发现」）。
- **票 04**：内核加不透明表 `session_owners`（不进 DTO → 线协议零变化），判定链固定
  **权限门 → 参数门 → 属主门**；`session_lifecycle_register` 补 `session:read`；
  注解槽做成「属主独占写入」而非票面字面的命名空间（理由见票 04 实施记录第 5 条）。
  2026-09-22 复核：交接旧版说的「对侧 `output-ring-fetch` 未过属主门」**不成立**——
  实现与三条用例对侧在 `cc74d76d9` 已自带（注释点名票 04），已在票 04 末尾记为「无遗留尾项」。
- **票 05**：总线访问控制由 **topic 形态**决定——`<plugin-id>::<name>` 是收件箱，
  只有属主与宿主可订阅/可发布；判定只看串，不查激活表/安装表（机制 A 会在属主未激活时漏判）。
  宿主定向事件（`pty:exit` / ws 五事件 / `mdns:found|lost`）改投该形态；legacy 旧串
  （`pty:exit.<own-id>`）**订阅面显式拒绝并回带新形态**，不留静默断流。
  互调回复道：订阅面对 WASM 关闭 + `ReplyHandler` 校验 `sender` == api 声明属主
  （SDK correlation id 是可猜的 `req-N`，改前实测伪造回复能被当成调用结果返回）；
  顺带修掉 `api_call` 的回复订阅泄漏。原语单一真源在 SDK `host::bus`，宿主与插件共用。
  移动端不跟演（代码与版本号未动），三处偏离清单在票 05 Comments 与 AGENTS §7。
- **票 03**：审批门禁从「覆盖良好的死码」变成激活路径上的闸门 —— `activation.rs::approval_gate`
  在**预授权之前**裁决（不持 `plugins` 锁，目录哈希走 `spawn_blocking`）：只作用 `UserInstalled`
  （随包内置来源沿用 ADR 0020 的构建信任域），无记录/哈希失配 → `NeedsApproval` + 拒绝激活
  （失配并撤销批准）；**生效集写进 `PermissionManager`**（只算不授 = 门禁可绕过），
  `effective_permissions` 的 `storage` 无条件插入与票 02 取消的默认位对齐。
  `compute_dir_hash` 排除插件私有库 `plugin.db` 及 SQLite 边车（**不排除会让「批准 → 启用 → 再启用」
  自判内容替换并撤销自己的批准**，这是本票最容易漏的一处）；存量兼容走 boot 自动批准一次 + `warn`。
  前端：`PluginApprovalDialog.vue`（列表页/详情页共用，`NeedsApproval` 时「启用」改为先审批后启用）+
  权限文案由 14 补到 **31** 条（zh-CN/en）+ 高危四位红标与后果文案。
  安装期补 `wasm_hash`（可选字段，**目前无生产者**：打包 CLI 不注入，与移动端现状一致）与
  zip 三类上限（512 条目 / 64 MiB / 32 MiB，按实际写入字节裁决）。
  双端偏离（`storage` 特例仍在移动端）记进 ADR 0020 修订记录。

## 8. 用户已确认的工作方式（本项目内）

- **一张票做完先提交再开下一张**；票据/spec 单独 `docs(scratch)` commit，实现各自一个 commit。
- commit message 用中文 conventional commits，**必须写实际跑过的门禁数字**（用户拒绝照抄票里的历史证据）。
- **禁止 commit message 出现 AI 协作者标记**（AGENTS §11）。
- 遇同 worktree 对侧在途改动：**不碰对侧文件、不抢构建锁、记证据等收尾**，不擅自 stash/checkout 对侧内容；
  **历史被对侧卷走时不改写对侧 commit**，取证写进票面并报告用户。
- 拆票偏好纵向 tracer-bullet + 前置 prefactor；资源上限类取舍优先「调用方声明 + 宿主上下限 + 越界 fail-visible」。
- 下沉按产品闭环并插件、**界面维持**、能力只经 `host-*` 原语；可单端先做完，另一端破损**列清单显式登记**
  （移动端代码与版本号一律不动）。
- 不确定的设计取舍先问，不猜；安全/架构红线（AGENTS §5/§8）不可静默越过。
