WasmApp Mobile · 应用运行平台原型 v0.3 · 品牌对齐版

移动端重构为 WASM 应用运行平台：终端、文件传输、AI Chatbox 各自成为独立 WASM 应用，在平台上运行、被统一治理；连接由各应用独立持有（平台无全局连接）。交互形态对齐「本地版小程序」。

本次评审改了什么（v0.1 → v0.2）

P0
v0.1 的色板不是移动端的真源
v0.1 用的是 Dracula 暗色（#0a0a0f + neon cyan #00d4ff）。核对仓库后：移动端真源是 warm 墨纸（--mobile-bg-primary #15130F / --mobile-accent #ECE8DC，见 mobile.css:7-140）。#00d4ff 只存在于终端 xterm 主题（config/terminalThemes.ts:66）。v0.1 文档里「视觉真源沿用移动端既有 Dracula 暗色」是错的，本版已改为真源值，并把 Dracula 收回到终端内容区的语法着色。
P0
版本号是幻觉
v0.1 写「wasmtime 47」，实际双端锁 48（desktop/src-tauri/Cargo.toml:95 / mobile/src-tauri/Cargo.toml:83，ADR 0019）；写「v2.0.0」，实际 2.1.1（bedcode-mobile/package.json:3）。本版已按真值修正。
P0
小字对比度不达标
v0.1 用 #6b7280 做 11px 辅助文字：在 #0a0a0f 上 4.09:1、在卡片 #12121a 上 3.85:1，均低于正文 4.5:1。#4b5563 更低（2.61:1）。本版改用真源 --mobile-text-secondary #9C9482（5.76:1）承载辅助文字，--mobile-text-muted 只留非文字用途。
P1
只有暗色、没有浅色；色板不可切换
真源含浅色 token（mobile.css:158-235）与 5 档主色色板（mobile.css:776-856）。本版补齐主题切换 + 色板切换，两者都按真源值。
P1
缺无障碍基线
v0.1 无 prefers-reduced-motion、无 prefers-reduced-transparency、无 :focus-visible、开关是 <span onclick>、行是 <div class="row">、状态点被当作装饰撒在列表上。本版全部改为语义元素并补齐降级。
P1
破折号与死代码
v0.1 含 31 个 em-dash（U+2014，分布在 17 行；其中 1 行是 CSS 注释，其余 29 个在可见文案里），en-dash 为 0，是典型的 AI 生成痕迹；本版可见文案 U+2014 / U+2013 计数为 0。另有 9 条 opacity="0"/".0" 隐藏路径 + 1 条零长度路径（共 10 条不渲染路径）与 2 条重复变体，已全部删除；无用的 back() 与未读取的 sc 变量也已移除。
P0
伪造的应用身份与版本号
v0.1 的详情页写 com.bedcode.terminal · v1.4.2。仓库里没有这个 plugin id（唯一的终端是桌面侧 terminal-session，id com.bedcode.terminal-session，type: internal-business，版本 1.0.0-beta）；三个移动插件真实版本也全是 1.0.0-beta，不是 v1.4.2 / v0.9.1 / v0.6.0 / v0.3.2。本版已删掉伪造 id 与假版本号，改为仓库真值；应用清单加「示例数据（非真实清单）」标注。未改的是「官方」徽标与各项体积 / 延迟数字：仓库里没有「官方」这一分类概念，数字也无从核对，落地前必须由数据源替换（属产品数据问题，不属设计问题）。
P1
自相矛盾的计数
详情页渲染 10 行权限却标「8 项已授权」，且 storage 明明是「默认授予」却用 badge off（停用样式）。本版按渲染行数改为「9 项已授予 · 1 项默认」，storage 改用已授予样式。
P1
缺安全区契约与 z-index 层级纪律
v0.1 无 env(safe-area-*)、底部内边距写死 calc(10px + 4px)；z-index 出现 4 / 5 / 55 / 60 等自造层。本版接入 --safe-area-top/bottom（真源 src/style.css:19-25，落地对应 mobile-header-safe / mobile-nav-safe），并把 z-index 收敛到 safe-stack 的 6 档（见 §3 注释）。
P1
命名与真源不一致
清单里插件真名是 AI Chatbox（小写 b），v0.1 全文写成 AI ChatBox。本版按 manifest 统一为 AI Chatbox。

品牌对齐（v0.3 新增）

应用 .scratch/2026-10-07-wasmapp-brand/brand-spec-mobile.md 的双色层架构：品牌琥珀固定，平台色板可切，两层永不互相覆盖。

层取值出现在哪谁决定
品牌层--brand-ember #FF9E2C标志、字标、品牌位圆点品牌（不可配置）
UI 层--mb-accent按钮、开关、选中态、进度条用户在「外观」里切换

落地改动四处：

  • 顶栏换成品牌标志 + 字标：Wasm<em>App</em>，App 用琥珀。原先是通用四格网格图标 + BedCode 文字。
  • 产品名改为 WasmApp（标题 / 顶栏 / 关于页 / 设置行）。桌面端 tauri.conf.json 的 productName 已是 WasmApp，这次是把移动端原型对齐过去。
  • 标志不再跟随用户色板。v0.2 的标志位用的是 --mb-accent，用户切到海蓝时标志会变青色，这是错的；现在固定琥珀。
  • 浅色主题换明度档，不换色相：#FF9E2C 在浅底只有 1.87:1，浅色主题下自动切到 #9F621B（文字 4.50/4.83:1）或 #C2701A（图形 3.39/3.64:1）。

没有改的：各 app 的图标与自带主题色（终端 cyan、AI violet、传输 emerald）保持原样。品牌规范只约束品牌层，app 图标是各自开发者的标识，不是 WasmApp 的品牌位；把四个 app 图标都刷成琥珀反而会丢掉「多应用」这条核心语义。

琥珀的边界：琥珀不是 UI 控件色。原型里没有把任何按钮、开关、选中态改成琥珀，因为它们属于 UI 层，归用户色板管。这条与桌面端一致（components/SplashLoading.vue 只在启动页用琥珀，主界面 accent 仍走用户色板）。

审计口径（两遍独立核对）

本版结论由两条独立路径得出，冲突处以事实核对为准：① 写作者用 WCAG 2.1 相对亮度公式逐对计算对比度、并用 mock DOM 跑交互逻辑（proto-dom-test.js，20 项断言全绿）；② 独立审计者重读 v0.1 全文 + mobile.css 全文，逐行枚举破折号与死路径。审计者纠正了写作者两处夸大的统计（em-dash「18 处」应为 31 个字符 / 17 行；隐藏路径「12 条」应为 10 条），也把范围扩到 v0.1 未列出的 22 处文字 + 4 处非文字对比度失败（共 26 处）。写作者则推翻了审计者一处误判：关闭码 4003 在仓库里真实存在（composables/useMobileConnection.ts:395，ADR 0031 认证类致命关闭 4001/4003），不应作为「未核实文案」删除。

已知偏离（保留，不修，理由随行）

  • 占位符对比度：--mb-input-placeholder 深色 2.15:1 / 浅色 3.41:1。真源值如此（mobile.css:66 / :223），本原型不本地改 token，以免造出平行色阶。占位符是提示而非唯一标签（标签在输入框之上或由上下文给出），但严格 WCAG 下算失败。
  • 非文字描边：输入框 / 标签 chip / 键帽描边对底色的对比为 1.25 到 2.08，低于 3:1，同样来自真源 token。
  • 开关状态：OFF / ON 轨道色差仅 1.53（暗）/ 1.12（浅），状态靠滑块位置 + aria-pressed 表达，不靠轨道颜色。
  • 多任务卡片边界：卡片面与页面底色差 1.03 / 1.14，边界靠 --mb-border-3（2.52 / 2.10）+ 阴影，低于 3:1。
  • 示例数据：官方 徽标与全部体积 / 延迟 / 进度数字是演示值，已在应用页标注「示例数据（非真实清单）」；终端 一行在移动端没有对应的真实插件（唯一的终端是桌面 terminal-session）。

三个核心概念

① 平台首页可被 wasm app 扩展：首页提供「快捷卡片槽位」，各 app 可向首页贡献卡片（终端的活跃会话、传输的进度、AI 的最近对话）。app 安装后自然出现在应用网格；卸载后槽位卡片随之消失。卡片标注由 xxx 提供，归属清晰；无卡片时显示空态而不是空白槽位。

② app 全屏独立界面 + 独立风格：点开 app 即进入它的世界，自带顶栏、自带 accent、自带交互范式（终端的快捷键条、AI 的对话流）。平台只叠加右上角一枚「胶囊」（··· 菜单 / ◎ 退出）。app accent 只作用于该 app 容器，不写回平台 token。

③ 平台统一治理 · 连接各自独立：「WASM 应用」页集中管理安装 / 停用 / 卸载、版本体积、权限开关（沿用 plugin-sdk-mobile/rust/src/permission.rs:7-45 的词汇）、存储与授权记录；运行时授权走平台统一弹窗（fail-closed）。连接不归平台托管：每个应用独立持有自己的连接（终端 ↔ 桌面主机、传输 ↔ 对等设备、AI ↔ 供应商），在应用页与详情页各自呈现与管理。

设计决策

  • 双色层：品牌层固定琥珀 --brand-ember（标志位），UI 层走真源 --mobile-accent（控件位，default 色板为象牙白 #ECE8DC，浅色模式为近黑 #1D1A14）。琥珀不得用于控件，色板不得改标志。详见「品牌对齐」。
  • app 自带 accent：app accent 属 app 私有主题，作用域限于该 app 容器，符合「一页一 accent」的纪律；app 图标是各自开发者的标识，不是品牌位，因此不刷成琥珀。
  • Dracula：只保留在终端内容区的语法着色（terminalThemes.ts 同源）；终端 app 的壳用 --mobile-terminal-bg，不再是 neon cyan 平台。
  • 圆角：卡片 12 / 控件 10 / 胶囊 999（图标方块 52px 取 15px），三档 shape lock，全原型无第四种。
  • 字号：采用 --font-size-* 在 360px 处的取值（10 / 12 / 14 / 16 / 18 / 24）。落地时这些值由 token 的 clamp() 提供，原型不复制公式。
  • 触控：所有可点元素最小 44px（--mobile-touch-target-min）；反馈用 :active，不用 :hover（触屏无效）。
  • 图标：全部内联 SVG，stroke 1.8 统一，无 emoji、无隐藏占位路径；状态点只用于真实语义状态（连接 / 运行 / 权限裁定）。
  • 落地对应：平台页走 --mobile-* token；app 界面由各自 wasm app 前端自带样式（scoped / inline）。

已确认裁决

  • 多任务入口 = 手势（上滑并停顿呼出，上滑卡片关闭），不设独立入口。
  • 权限模型沿用移动端现有词汇真源（permission.rs：terminal:input/output、session:read/write、fs:read/write、network:http、peer、mdns、bus、ui:*、system:open；storage 默认授予不可关）。
  • 应用统称 WASM 应用；连接归各应用独立持有与管理（平台无全局连接）。

待裁决问题（供评审）

  • 首页槽位数量上限与排序策略（按最近使用？用户固定？）。原型当前按「最近贡献」排序，未设上限。
  • 高风险权限（fs:write 全量 / peer）是否要求运行时二次确认？
  • 浅色模式下 app 自带 accent 的取值由谁定义（app 作者自报 vs 平台强制降饱和）？原型暂按 app 作者自报处理。
